# K9: train/val near-duplicate leakage

## Question and prediction
K8's plausibility gate failed: our 14M models score 0.47–0.49× SmolLM2-135M's bits/char. The registered consequence was to rule out train/val leakage before trusting any absolute loss number.

**Prediction** (registered in v0.4.30): fewer than 1% of val docs are near-duplicates; the val overlap is within ±5 points of a pseudo-val baseline; dropping near-duplicates moves E0's bits/char by < 2%.
**Criterion**: PASS if near-dup val docs are < 1% AND the loss effect is < 2%. On FAIL, rebuild val with near-dup removal and re-score.

## How to run it
`bash tools/launch_cpu_job.sh --name k9 -- ~/.venvs/gogeta/bin/python experiments/checks/k9_leakage.py` (CPU, 200 s, peak ~1 GB). Use `--selftest` and `--plan` for dry runs.

- **K9a: FAIL** (41.7% vs < 1%).
- **K9b: FAIL.** E0 scores **0.101 bits/char on the 1,667 near-dups** (CPU), and the full-val **0.2209 becomes 0.2779 (+25.8%)** without them.
- **Interpretation:** val and pseudo-val overlap equally, and the controls are clean, so this is **corpus-level self-duplication**, not a split bug. Many LeetCode/MBPP-style problems recur in near-identical variants (median of two sorted arrays, four sum, count-and-say, ...), and a random split puts copies on both sides. Boilerplate doesn't explain it.
- **Prediction scorecard:** (1) miss; (2) hit; (3) miss.

## Consequences
- Every training-time `val_loss` / `val_bits_per_char` so far (E0, E1, E2, E3, E9, E10, K7) is measured on a val that is ~42% near-memorisable. **Absolute numbers are inflated.** Comparisons may be confounded if architectures memorise repeats differently (attention vs GDN recall).
- **Registered action:** rebuild val with near-dup removal (rigor workstream A1: the clean-val doc list and manifest) and re-score every checkpoint, doc-level, on the clean val.
- Phase 2b's primary metric moves to clean-val doc-level bits/char, which A2 documents as a dated analysis-plan deviation made before any Phase 2b result. A memorisation-gap metric (near-dup minus clean bits/char) is added per model.
- **Training-set dedup** (`code-py-v2`) is being sized by A1. The future factorial should run on deduplicated data (A3).

## Caveats
The boilerplate ranking is among query 13-grams, not global train. Token 13-grams miss paraphrases, so MinHash (A1) may find more. The near-dup loss was scored on CPU fp32, while the full-val figure (from K8) is GPU bf16.
