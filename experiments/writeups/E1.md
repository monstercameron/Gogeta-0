## What it means, in plain English

> **We replaced most of the expensive part of the model with cheaper parts, and it got *better*, not worse.**
>
> The baseline ([E0](E0.html)) uses full attention in all 6 layers. That's like **rereading the whole document every time you write a word**: thorough, but the cost explodes on long documents.
>
> E1 keeps just **one** full-attention layer. The other five use two cheaper tricks:
> - **Gated DeltaNet** layers keep a **running set of notes** about everything so far, a fixed-size memory they update as they read, rather than rereading.
> - **Sliding-window** layers only **glance at the last ~256 tokens**, like checking the previous few lines.
>
> **Result:** E1 predicts code **3.6% better** than E0 while using slightly *less* compute. It matched E0's *final* quality after only **84% of the training**. It's the first real evidence for one of FusionDance's three ideas: you don't need expensive full attention everywhere.
>
> **The catch:** a 3.6% better *score* didn't mean better-looking code in our handful of samples, and it took longer on our laptop. The cheaper layers do fewer calculations, but the software that runs them is less optimised than standard attention.

## What we tested

Same width, same depth (6 layers), same data and training recipe as E0. Only the layer *types* changed:

| Position | E0 | E1 |
|---|---|---|
| 1 | full attention | sliding window (last 256 tokens) |
| 2 | full attention | Gated DeltaNet (running memory) |
| 3 | full attention | Gated DeltaNet |
| 4 | full attention | sliding window |
| 5 | full attention | Gated DeltaNet |
| 6 | full attention | **full attention** (the only one) |

14.2M parameters (11.1M excluding the word table): about 4% more than E0, because a Gated DeltaNet layer is a bit bigger than an attention layer at this width.

## Breakdown of the findings

1. **E1 beats E0: 0.585 vs 0.606 validation loss (−3.6%).** It's ahead at *every* checkpoint, from 8M tokens to the end, so it isn't a lucky final number.
2. **Less compute per token:** 1.82e16 training FLOPs vs E0's 1.94e16 (−6%). Better *and* cheaper in arithmetic.
3. **Data efficiency:** E1 reached E0's final checkpoint loss (0.629 on the quick check set) at about **169M tokens**, 84% of the budget.
4. **But slower in real time:** 39 minutes vs 23 (about 86k vs 143k tokens/s on average). Standard attention has decades of hardware optimisation behind it; the Gated DeltaNet kernels are newer, and our sliding-window layer still uses a simple, unoptimised implementation.
5. **Memory that doesn't grow:** five of E1's six layers keep a fixed-size state no matter how long the text gets. At our 1,024-token length that doesn't show up yet: peak training memory was actually higher (7.1 GB vs 4.8 GB), and that's working memory *during training*, a different thing from the memory a model needs per token of text. The fixed-state advantage matters for long inputs, which we haven't tested yet.
6. **Samples:** solved the palindrome task (correct function and asserts) and wrote a sensible `binary_search` docstring with examples. But its `fibonacci` and `Stack` completions were the *least* coherent of the three models. On a handful of samples, a better loss didn't look like better code, which is why a test that runs the generated code is on the to-do list.

## Caveats

- **One seed.** A 3.6% gap at this scale is probably real (it held at every checkpoint), but the replication runs that would confirm it were interrupted.
- Short context only (1,024 tokens). The big promised win of these layers is on *long* inputs, which we haven't measured yet.
- More parameters than E0 (+4%). A small part of the gap could come from that rather than the layer types.
