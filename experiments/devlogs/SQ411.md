# SQ411: close the `__eq__` reward-forgery route

**Status:** done · **Verdict:** a solution returning an object with an always-true `__eq__`, `__ne__`, `__lt__`, `__gt__`, `__contains__` or `__bool__`, or a subclass of a builtin type that overrides them, now scores 0 on every probed assertion form; the probe's 14 forgery arms that passed 1/1 on the committed harness (HEAD, after SQ373) all score 0/1 after the change; honest passes and fails are unchanged · **Links:** `post_training/rewards.py` (`_HARNESS`), `post_training/test_rewards.py` (`TestEqForgery`), `experiments/checks/reward_forgery_probe.py` (new arms; `REWARDS_ROOT` selects the harness copy), table `experiments/checks/results/reward_forgery_probe_sq411.txt`

## Change
In the grader process, BEFORE the fork (so nothing the solution does can touch the rewriter), every test is parsed and rewritten with an `ast.NodeTransformer`, then compiled; the worker only executes the compiled code objects. Rewrites: every non-identity comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`, `in`, `not in`, including chains, with walrus temporaries so middle operands evaluate once) becomes `__sc__(op, a, b)`; the truthiness of an `assert` test (`assert f(x)`), of `not x`, and of `and`/`or` operands inside an assert goes through `__st__` / `__sn__`. The helpers (bound before the solution runs, injected into each test's fresh namespace) first require both operands to be builtin value types by EXACT type (int, float, complex, bool, str, bytes, bytearray, None, range, Fraction, Decimal, date/datetime/time/timedelta) or list/tuple/set/frozenset/deque/dict/OrderedDict/defaultdict/Counter whose items, keys and values are themselves such; anything else (a custom class, a subclass of a builtin) makes the comparison or truthiness False, so the assertion fails (fail closed; for `!=` too). Only then is the builtin operator applied, so no solution-defined dunder method is ever called. A test that does not parse counts as failed with its SyntaxError. `is`/`is not` are left alone (identity cannot be overridden).

## Caveats (documented in the harness header)
- Fail-closed by design: an honest solution that returns a non-builtin type (a user class, a numpy array, a dataclass) fails equality assertions against it; datasets whose tests compare custom objects need their expected values built from builtin types. Reward datasets with `assert candidate(x) == [..]` / `abs(...) < eps` style tests (HumanEval, MBPP, the repo's algorithmic corpus) are unaffected.
- Not closed: a solution-defined helper that the test calls and whose own code lies (e.g. a test `assert helper(f(x))` where `helper` is in the solution), comparison via methods (`.equals`), `any`/`all` over forged iterables, and the pipe-protocol imitation of SQ373. Process sandbox, not a security boundary.
