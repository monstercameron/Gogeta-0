## 2. Critique

**2.1 R1 is not "the cost of spelling".** A4a vs A3mx changes three things: the 8k softmax head becomes a byte decoder (312k params, config `computed.params.decoder`); the trunk's gradient now comes only through the byte loss; and the per-token loss includes EOT (code-read, c2f docstring). R1 measures spelling plus objective change together. PREDICTIONS A4 says "spelling a token byte by byte costs a little", which should say so. The good part: the metric is per target token of identical canonical tokens, so it is directly comparable with the BPE head (code-read).

**2.2 R2 is not a sharing test.** A4a and A4b differ in r_b (2 vs 1) and in the per-pass auxiliary loss (`refine_aux_weight` 0.5 vs 0.0; both configs). R2 is "second pass plus per-pass loss", yet it is labelled "sharing helps" (quoted). The clean sharing contrast is R3 (A4a vs A4c), which keeps the same contractive and aux settings. But A4c is also narrower (`refine_mlp_hidden` 170 vs 512) and costs 0.963x vs 1.003x A3mx's train FLOPs (configs). So R3 is parameter-matched and about 4% cheaper, not "equal FLOPs". The README's H-C2F sentence claims "an unshared decoder of equal FLOPs" (quoted, Byte Quest section). A shared-vs-unshared test at equal FLOPs needs an unshared full-width arm, which has twice the decoder parameters (computed; still about 1% of the model).

**2.3 The 3-seed rules are probably underpowered.** Viability is "paired 95% CI upper bound <= +3%". Two variance sources give very different answers (computed; assumptions labelled):
- A2's reported interval (±1.05 pts from 3 seeds, t = 4.30) implies a paired seed sd of about 0.42 pts, so an A4 paired CI would be about ±1.0 pt.
- The F2 blinded seed sigma (0.00873 per run, quoted in README) implies a paired sd of about 1.2 pts, so ±3.1 pts for 3 seeds.
The byte arms have never run at more than one seed (SQ374), so their seed sd is unknown, and the registration states no power assumption. If the second figure holds, R2 (-1.5%) and the viability rule cannot be decided unless the true effect is at least about 3 pts. Pinning down the sd comes first (I2).

**2.4 The metric is not the primary one.** A4 uses in-training val loss. The staged configs set `eval_seqs: 128` (about 131k tokens), and the sampling error of that number is not reported. The registration says clean80 doc-level scoring "is not wired for the byte decoder" (quoted). AGENTS §0 and the ledger make clean80 the primary metric. K9 found 41.7% of v1 val near-duplicated (quoted), and SQ238 found the v2 dedup alone moves v1-scored results by +1.62% (quoted). A viability verdict on non-clean val is not the thesis' number until a byte clean80 scorer exists.

**2.5 Config and budget inconsistencies (quoted vs config).**
- The A4 train blocks say `max_tokens: 20000000`. PREDICTIONS A4 says 200M, and a3mx.json says "200M via --max-tokens". This is probably a launch override, but a 20M run would not match the registration. Confirm the launch command.
- A4 configs say "lr 6e-3, not tuned for the decoder" (code-read). The byte LR is 0.006 in configs but 3e-3 in DEVLOG for E13. Neither is tuned at 200M.
- `a4x1a` (frozen A2s trunk, seed-2 checkpoint) gives the decoder-only bar: A2s val 1.0910 nats/token (quoted from its summary, in the config notes).

**2.6 SQ374 is not a precise number.** It is one seed with no byte LR tuning, yet the README reads it as a +63% effect. AGENTS §6 says controls are tuned before use. It supports "fixed P=4 is clearly worse here", not a magnitude. The default design also drops fixed patches, so E13's granularity question (P = 2/4/8, SQ372) is no longer answered by the default path.

**2.7 What the 13:10 review got right, and what is now fixed.**
- Its 2.1 (init depth) is fixed in code: `decoder_depth()` = r_b x len(refine_blocks) feeds `_init_local`, and the trunk keeps its own init (code-read, c2f.py 336-355). Its truncation concern does not apply: A4's trunk has `bptt_loops = loops = 2`, and the byte loop has no truncation.
- Its 2.2 (ternary leak) is fixed: `local_config(ternary=...)` sets decoder precision explicitly (code-read, c2f.py 134-140, 301); `decoder_ternary` defaults to false.
- Its 2.4(c) (MoE aux dropped) is not a problem: `train_c2f.py` adds `aux["loss"]` to the loss (code-read, lines 261-262).
- Still open: 2.3 (ternary scope: the decoder is full precision and A3mx's ternary is experts only), 2.5 (draft acceptance at fixed r), and 2.6 (the copy fix must stay outside the loop).

**2.8 Wording against AGENTS §0.**
- README "Why bytes" says "No tokenizer to train or ship" and "robustness to odd spellings" (quoted, line 88). That describes the fixed-patch design the project just abandoned. The default A4 keeps the BPE tokenizer, so both claims are untested for A4.

## 3. Alternative ideas (all (spec) hypotheses)

**I1. Clean80 for the byte decoder, first.** Hypothesis: the A4-vs-A3mx gap on clean80 bits per byte agrees within 0.5 pts with the in-training gap. Cheapest test: score the byte decoder doc by doc (sum NLL over bytes and EOT, divided by doc bytes) on A2s and A3mx checkpoints; inference only, about 10 GPU-min, or CPU on 128 docs. Changes plans: a sign flip voids every in-training A4 verdict. Novelty: fills the registration's own limitation; SQ385 is per-position, not this.

**I2. Power from data we already have.** Hypothesis: the paired seed sd of E1 vs E10 at 200M is at most 0.5 pts, so n = 3 detects effects of about 1.5 pts. Cheapest test: paired differences from the Phase 2b 7-seed E1/E10 runs (quoted, RTX 5090); CPU, minutes. Changes plans: if the minimum detectable effect is above 2 pts, add seeds 8-11 before any A4 verdict. Novelty: extends SQ253 (which covers SQ243 only) to the A4 rules.

**I3. Where the spelling cost sits.** Hypothesis: most of A4's extra nats are at slot 0 (choosing the token's first byte, which repeats the BPE choice). Within-token slots add little, so the refinement loop has little to fix. Cheapest test: decompose per-slot and EOT NLL from `last_aux` (`slot_loss` and `eot_nats_per_token` are already logged, code-read) on a 20M byte-decoder checkpoint; CPU. Changes plans: if slots 1 and up carry most of the gap, the loop has a target; if not, drop it from A4-style designs. Novelty: the slot logs exist and no SQ uses them.

**I4. Separate the confounded pieces (2x2 plus a FLOP-matched arm).** Hypothesis: R2's gain comes from the per-pass aux loss, not the second pass. Arms at 20M tokens: r_b in {1, 2} x aux in {0, 0.5}, plus A4d (unshared, full width, FLOP-matched to A4a). Cheapest test: four or five 20M GPU runs, about 5 min each (spec: estimated from the E1 throughput). Changes plans: if aux explains R2, rename the result; if A4d beats A4a by more than 1 pt, sharing costs at equal FLOPs. Novelty: decoder-level arms; SQ381 is trunk-level aux.

**I5. Does the byte decoder need to exist for head cost?** Hypothesis: a factorized 8k head (two-level or adaptive softmax) recovers the full head's loss at a fraction of its FLOPs, so the README's "8k head = 21% of E1's per-token compute" (quoted) does not require spelling. Cheapest test: swap the head on a 20M E1-style model; GPU 5 min or CPU at tiny scale. Changes plans: a result within 0.5% voids the byte track's FLOP case, which then rests on robustness alone. Novelty: new; SQ1 covers the embedding table, not the head.

**I6. Cached-trunk decoder sweep (amends SQ216 and SQ207).** Hypothesis: the decoder-only spelling cost on a frozen A2s trunk is at most 1% against that trunk's own BPE head. Cheapest test: cache A2s seed-2 states for about 2M tokens once (about 1.5 GB in bf16), then train the I4 arms for five decoder seeds each on the cache. Decoder training is cheap, so five seeds per arm are affordable. Changes plans: over 3% means spelling costs capacity; at most 1% means A4's joint result measures trunk co-adaptation. Novelty: the caching and five-seed power are new; the X1 configs exist as `a4x1*` but are not run.

**I7. Test the pitch's robustness claim on A4.** Hypothesis: A4 is not more robust than A3mx on identifier typos and rare or non-ASCII names, because the trunk still reads BPE tokens. Cheapest test: SQ187's perturbation set on A3mx vs A4 once A4 trains; CPU inference. Changes plans: if A4 wins by more than 2%, the byte track has a reason beyond FLOPs; if not, drop robustness from the pitch. Novelty: SQ187 exists for E1 vs byte-E1; this retargets it at the default design.

**I8. Batch-1 decode budget for the byte decoder.** Hypothesis: the decoder adds at least 30% per-token latency at batch 1 in eager mode. Cheapest test: time a full re-forward per generated token (no cache) for A3mx and A4a over 256 tokens; about 5 GPU-min. Changes plans: if yes, goal 6 needs a fast path (CUDA graphs per SQ375, or a one-row head) before any byte claim. Novelty: extends SQ362 and SQ375 to the byte decoder.

## 4. The one experiment I would run next

I6 with I4 folded in, run before any A4 verdict. Freeze the A2s seed-2 trunk and cache about 2M code-py-v2 tokens of states once. Train four decoder arms (single pass; shared r_b = 2 with aux 0.5; shared r_b = 2 without aux; unshared full width, FLOP-matched) for five decoder seeds each, with A2s's own BPE head on the same tokens as the bar. Score clean80 bits per byte (I1).

Why: it is the only design that gives five seeds per arm cheaply, which the A4 rules cannot afford, and it separates the aux loss from sharing, which R2 confounds. (spec) Predictions: spelling cost at most 1%; aux explains most of R2.
Limit: a frozen trunk tests spelling cost, not joint training, so it cannot replace A4.
Cost: one GPU job of minutes to about an hour (spec, not measured), within the one-GPU-job rule (AGENTS §5). It amends SQ216, the noise-floor arm that already gates X1.
