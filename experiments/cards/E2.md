# E2: Looped core block

## Question and prediction
- **Question:** does a shared [GDN, GDN, SWA] core looped r times match a deeper unshared model with fewer params, and keep improving with more loops?
- **Prediction:** registry E2.prediction (committed `0dc7491`): 5 of 7 claims hit; both misses say extra loops are worse than expected.

## How to run it
- Config: `configs/e2_looped.json`: prelude `[swa]` → core `[gdn, gdn, swa]` × r → coda `[attn]`; train r ~ U{1..7} per batch, backprop through the last 4 loops; injection `h = h + inject([norm(h), norm(e)])`
- Launch: `bash experiments/launch/E2.sh [--seed N]`
- Code version: `0dc7491` · Compute: 80.3 min, ~42k tok/s avg, 3.87e16 FLOPs

## Results
Loss vs eval loops: r1 0.6694 · r2 0.6272 · **r4 0.6186** · r6 0.6239 · r8 0.6328 · r12 0.6540. K6 (`experiments/checks/results/K6.json`): no convergence (relative change 0.085 at k=12); per the reviews, the state norm grows ~linearly (~4.6–5 × ‖h₀‖ per loop) with increments aligned to h, i.e. the loop mostly inflates the state. ## How to reuse this
- **Inference-only loop diagnostics** without training: K6 did this; SQ14 (rescale h before the coda) and SQ21 (post-training quantisation vs loop count) are designed to reuse this checkpoint.
- Baseline r-curve for any loop fix (contractive injection SQ15, step scaling SQ16, consistency loss SQ17, state norm SQ18): a fix must flatten or improve L(r>4).
- **Don't** use it as evidence that "loops don't work" in general: the E9 control is missing, LR is untuned, tokens/param is ~21 (published looped wins train far longer).

## Caveats
Single seed (C7 needs ≥ 2 seeds); E9 (unlooped twin) pending; untuned LR; the in-loop SWA uses an O(n²) dense-mask kernel.
