## 2. Critique

### 2a. Architecture (gogeta/model.py)

1. **The loop is additive with no scale control.** `h = h + inject([norm h, norm e])` (l.270-271) has no loop-boundary norm and no per-pass gain, so the residual norm grows with r. K6 and C39 show this. It is the most likely mechanism behind C7. Fix the scale (SQ14/16/18) before adding loop arms.
2. **Train/eval mismatch.** r ~ U{1..7} in training (l.48-49), eval default 4 (l.47), `bptt_loops=4` (l.50). For r >= 5, the first r-4 passes get no gradient (l.267-269). SQ19 tests this. Init scale uses `effective_depth()` at loops=4 (l.246-253), so every training draw uses an init calibrated to r=4. No queue item covers that second point.
3. **Unique parameters are not separated from depth.** E32 vs E2 is a clean shared-vs-unshared test: same depth (14 block applications) and FLOPs within 4% (computed from staged-table.md), but E32 has 2.75x the unique params. The width arms are less clean. E34 (E9 widened to d=576) has the same unique params as E32 (26.07M vs 26.04M, computed) and FLOPs within 4%, yet scores 0.2834, which is 14% worse than E32 (computed). Its registered predictions (PREDICTIONS.md l.327: "within ±3% of E32", "beats E2 by 1 to 6%") both miss: E34 beats E2 by 0.4% (computed). v0.4.80 does not record the miss. E30 and E31 run at LR 3e-3 while E32 to E34 run at 6e-3 (staged-table.md), so LR is confounded with the width arms. The registration says a shortfall above 3% is uninformative about width, but nothing yet tests that with an LR-tuned width arm. The depth-vs-params reading is therefore open.
4. **Dense FusionDance trails Llama by about 3.5%, not only E0.** E30 (dense, E1's params, LR 3e-3) scores 0.2770 vs E10's 0.2677 (5090 mean): +3.5% (computed). E0 is about 3.7% behind E10 (README). The E1-vs-E30 gap (3.4%, computed) is a mixer effect inside our own dense family. E1's tie with E10 means that gain only offsets the dense stack's handicap.
5. **Efficiency is FLOP-analytic.** SWA is dense-masked (l.8-9; C12 WRONG FOR OUR CODE). E1 runs at 0.94x E0's FLOPs and about 0.6x its speed (research-code-moe.md §3.9, citing design-rigor §2). The "linear time" pitch holds for FLOPs only until SQ72 lands.
6. Minor: `Attention._mask` cache is unbounded (l.126-134; SQ275).

### 2b. Method

1. **Multiplicity.** Waves 4 to 6 add about a dozen registered tests (S1-S3, P1-P2, D1-D3, I1-I4, the F2 decision). Holm covers only the two Phase 2b comparisons. No family rule spans the waves.
2. **Power vs predicted effect.** At 4 seeds the MDE is about 0.9% (SQ253, quoted). Predicted gaps are 0.2% (S1/S2, "tie") and 0.5 to 2.5% (I3, whose low end sits below the MDE). A tie cannot be falsified without a registered equivalence margin; C196's ±1% is the only one.
3. **Controls are not LR-tuned.** AGENTS §6 requires control tuning before use. K7 covered E10 and E1 only. E0 has never had its own sweep, and the width arms sit at file LRs that differ across arms (§2a.3).
4. **The metric is mostly synthetic code.** clean80 keeps about 48% of algorithmic docs and 77% of synthetic ones (SQ225, quoted). Every "sum of parts" verdict is on this mix. SQ250 and SQ252 are registered but unrun.
5. **Regime.** Nearly every new test runs at 20M (the F-series, the SQ200 tuning, SQ241 at 4 seeds), while the headline claims live at 200M. The 200M depth evidence is one seed per arm.
6. **Two datasets in one wave.** SQ243 and SQ241 use v1; F2 uses v2. SQ238 is the bridge and is not yet read, so a cross-wave comparison is not valid yet.
7. **Definitions.** C197's proposition says "unique parameters"; the evidence concerns depth and sharing. AGENTS §5 makes definitions immutable, so C197 should be superseded once the §4 discriminator has run.

### 2c. Is E60 stage 1 the right first MoE experiment?

Partly. The design is sound: dropless top-2 at matched active FLOPs, a frozen-router control, a total-param dense control, a stated power calculation and causality rules. It is not the right first experiment, for four reasons:
- It adds width at fixed depth, the arm class that E30 and E34 suggest does not help. The nearest in-repo evidence is null or LR-confounded, so M1 (-1.8%) has no support yet. Lower the prior until §4 is in.
- It runs on v1 (41.7% near-duplicate train docs). The draft's own M7 flags memorisation, and a capacity gain is most exposed there. Wait for SQ238.
- Stage 2 at n=4 is pre-declared INCONCLUSIVE: its own sizing rule gives n=21 at sigma 0.8%. About 3.5 GPU-h would buy a result the plan already calls inconclusive.
- E60c (dense 2048) is a second width arm at fixed depth, so it should share the §4 LR grid.

Verdict: keep E60a/b/c at 6 seeds, but gate it on the LR-fair discriminator (§4), on SQ238, and on a registered TOST margin. Stage 2 should be re-sized, or moved to 20M where sigma is cheap to measure first.

### 2d. The init 2x2 (SQ200 + SQ234)

Sound in structure: a full 2x2 of init by {FusionDance, Llama}, shared seeds 0 to 3, shape-matched arms, decision rules written before data, and I4 as a conditional. Four fixes:
1. **No LR per init.** Flat init without residual scaling (l.250-256) plausibly shifts the best LR (spec), so the init effect mixes with an LR-by-init interaction. Add a 20M grid {1e-3, 3e-3, 6e-3} for E0-gogeta, E0-flat, E10-gogeta and E10-hf (12 runs, about 10 min on one 5090) before the 200M arms.
2. **"Init explains half the E0-to-E10 gap" is not isolated.** E0 and E10 also differ in RoPE layout and eps (22:30 review, critique 2). Name that as a third factor, or state the result as init plus implementation.
3. **I3's range (0.5 to 2.5%) starts below the 0.9% MDE.** State I3 as "at least 0.9% or inconclusive".
4. **Unequal seeds.** E1-gogeta has 7 seeds and E1-flat has 4. The paired contrast uses seeds 0 to 3 only; say so in the rule.
