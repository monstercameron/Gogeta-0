# K1: memory and time vs context length

## Question and prediction
- **Question:** does our SWA really cost O(n·w), and does GDN keep a fixed-size state with linear time?
- **Prediction (committed before running):** `experiments/checks/PREDICTIONS.md`, section "K1", commit `f1b4ebd`. SWA time and memory exponents ≈ 2 (dense mask); attention time ≈ 2, memory ≈ 1; GDN ≈ 1 for both; streaming max |diff| ≈ 1e-5.
- **Pass criteria:** C12 holds only if SWA time and memory exponents are both ≤ 1.3. C15 is VERIFIED (kernel level) if GDN time exp ≤ 1.3, streaming max |diff| ≤ 1e-3, and the state shape is constant across n.

Setup: one mixer module per kind (`Block(kind).mixer`), d=384, 6 heads, w=256, batch 1, forward only, no_grad, bf16 autocast, n ∈ {1k, 2k, 4k, 8k, 16k}. Timing uses `bench_ms` with 5 warm-up and 30 timed iterations. The SWA mask is built during warm-up, so time excludes building it. The mask cache is cleared before each memory measurement. Exponents are log-log slopes over n ≥ 4096.

## How to reuse this
- `part_a()` is a generic harness: drop in any mixer module and get time and peak-memory exponents vs n. Use it to check a block-sparse or flex-attention SWA before re-testing C12.
- `part_b()` is the template for streaming-equivalence tests of any recurrent kernel that takes `initial_state`.

## Caveats
- At batch 1 the GPU is under-utilised, so the time exponents are biased low. Attention's 1.26 (predicted ≈ 2) and GDN's 0.66 reflect launch-bound timing, not asymptotics. The memory exponents are the cleaner signal.
- The diff is exactly 0.0 because the split falls on a chunk boundary (2048 is a multiple of 64). A split inside a chunk was not tested.
- Single seed and single device. Mixer only (no MLP and no full model).
