# SQ339: post-hoc split of the ternary cost (weights vs int8 activations) on the 200M F2 cells

**Status:** done (descriptive, not registered) · **Verdict:** int8 activations alone cost +0.11% (000) / +0.09% (100) post hoc; ternarising the weights of a full-precision model costs +769% (000) / +197% (100), so post-hoc quantisation says nothing about the trained +15.8% except that the activation half is negligible · **Links:** script `experiments/checks/sq339_ternary_split.py`, shared CPU code `experiments/checks/sq339_cpu.py`, validation `experiments/checks/sq339_cpu_validate.py`, results `experiments/checks/results/sq339.json`, `sq339_cpu_validation.json`

## Question
Is the +15.8% ternary cost (cell 001 vs 000, best LRs, sq263.json) mostly the int8 activations or the ternary weights? Complements SQ192 (a training arm).

## Method
Cells 000 (14 dense attention blocks) and 100 (GDN hybrid), trained in full precision, best-LR runs (E20/E24 at 3e-3), seeds 0, 1, 2. At eval time, every `make_linear` layer (attention qkv/o, SwiGLU up/down, GDN q/k/v/gate/o, re-injection: the layers BitLinear replaces; not embeddings/head, norms, GDN a/b, convs) is wrapped with the BitLinear operations of `gogeta/model.py`: absmean ternary weights (per-tensor scale), per-token int8 absmax activations, no STE needed. Arms: none, weight-only, activation-only, both. Metric: aggregate bits/char on a fixed 300-doc subset of the clean80 docs (random.Random(0) over the 2,333), window 1024 (K8 protocol), fp32 CPU, GDN via a chunkwise torch kernel. Penalty = 100 * (bpc_arm / bpc_none - 1), i.e. log-scale ratio as %. git 36acccc.

CPU path validated (seed 0, all 2,333 clean80 docs, fp32 CPU vs the GPU/bf16 fleet number): 000 -0.015%, 100 -0.011%, 010 -0.013%, 111 +0.002% (`sq339_cpu_validation.json`). The chunkwise kernel matches the per-token fp32 reference to 5e-7 (output) and 3e-6 (state). The docs are the v1 `docs_val.jsonl` clean80 set (K9 overlap < 0.8), exactly what the SQ263 fleet scorer used; the v2 dataset itself is not on this machine and v2 and v1 share one tokenizer (sha256 identical).

## Result (n = 3 seeds, penalty vs the unquantised model, mean, sd, 95% t-CI, df 2)
| cell | weight-only ternary | activation-only int8 | both |
|---|---|---|---|
| 000 dense | +769.3% (sd 74.2; CI +585 to +954) | +0.11% (sd 0.02; CI +0.06 to +0.16) | +769.8% |
| 100 GDN | +196.8% (sd 14.8; CI +160 to +233) | +0.09% (sd 0.01; CI +0.06 to +0.12) | +197.2% |

Per seed (000): weights +702 / +849 / +758%, activations +0.13 / +0.11 / +0.09%. Per seed (100): weights +211 / +198 / +182%, activations +0.10 / +0.08 / +0.10%. Trained ternary reference: +15.75% (cell 001 vs 000, 3-seed means, full clean80).

## Reading and caveats
- Nothing was trained with the quantiser, so the weight-only numbers are the cost of ternarising a model that never saw it: not comparable to QAT's +15.8%. What the table supports: eval-time int8 activation quantisation is nearly free (about 0.1%), so the QAT gap is not an activation-precision effect that post-training could reveal; it lives in the weights (or in training with the quantiser). It does not say how the +15.8% splits between weights and activations under QAT (that is SQ192, a training arm).
- The weight/activation effects need not add; "both" is about equal to weight-only here because the weight damage dominates.
- GDN cell 100 is hurt about 4x less than dense by post-hoc ternary weights (+197% vs +769%), but this is one architecture pair at one scale, descriptive only. The seed sd is large (10% of the penalty) because post-hoc error depends on each checkpoint's weight distribution.
- 300 docs (about 90k tokens): penalties are paired within doc subset, so subset noise cancels in the ratios; the absolute bpc is not the full clean80 value. Descriptive, not registered.
