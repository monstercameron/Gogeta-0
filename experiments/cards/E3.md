# E3: Ternary weights on the E1 stack

## Question and prediction
- **Question:** how much quality do BitNet b1.58 ternary weights cost at 14M params? Only the weight precision changes vs E1.
- **Prediction:** registry E3.prediction (committed in v0.3.4, before any run). Decision rules: ≤ 3% nearly free · 3–10% expected · > 10% → try the BitNet 2B4T recipe (SubLN, two-stage LR/WD).
- **Supporting local evidence:** K4 found the ternary gap at tiny sizes is 15.3% / 13.8% / 10.5% (d = 64 / 128 / 256, ~20M tokens), shrinking with size. E3 is d=384 with 10× the tokens, so expect it at or below the low end of that trend, pending E10's LR tuning.

## How to run it
- Config: `configs/e3_ternary.json` (= E1 + `ternary: true`; 33 BitLinear modules, 11.06M of 11.09M non-emb params ternary)
- Launch: `bash experiments/launch/E3.sh [--seed N]` (`--dry-run` first; refuses while code is dirty or the GPU is busy)
- Compute (estimated): ~40–50 min, about E1's 39 min plus quantisation overhead (K2: BitLinear is slower than nn.Linear in our code)
