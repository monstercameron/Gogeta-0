# SQ378: ternary packing and reload parity (A2s, seed 2)

**Status:** done (descriptive, not registered; one checkpoint) · **Verdict:** the 36 BitLinear layers of A2s (11.2M of its 18.2M parameters) pack to 2-bit codes + one fp32 scale each: 2.80 MB instead of 44.8 MB (16.0x), and the whole packed file is 30.9 MB vs 73.0 MB for the training checkpoint (0.424x; the full-precision rest, mostly the 8192 x 384 tied embedding and the full-precision prelude/coda/inject, is 40.7 MB and now dominates). Reloaded, the packed model scores 0.281729 bits/char vs 0.281741 fake-quant (-0.004%), max |logit diff| 0.249 on 20 docs, argmax agreement 99.82% · **Links:** script `experiments/checks/sq378_ternary_packing.py`, results `experiments/checks/results/sq378.json`; packed file `~/fusiondance-data/scratch/sq378_A2s-20261123-170724-s2.packed.pt` (not in the repo)

## Method
A2s-20261123-170724-s2 (200M tokens, ternary core with full-precision prelude/coda/inject, `ternary_fp_ends`). For every BitLinear: codes = round(w / s).clamp(-1, 1) with s = mean|w| as in the forward; stored as code + 1 in two bits, four per byte, plus s as fp32. All other tensors stay fp32 in the same file (`torch.save`). Unpack into a fresh model whose BitLinear layers use codes x s directly (not re-quantised) with the same per-token int8 activation quantisation; parity vs the original fake-quant model on the first 20 docs of the 300-doc clean80 subset (truncated to 256 tokens) and bits/char on all 300 docs (fp32 CPU). Contrast: the naive reload (put codes x s into the stock BitLinear weights).

## Reading and caveats
- The reload is not bit-identical (logit diff 0.25) because the original forward computes w + (w_q - w) and x + (x_q - x) (straight-through form) while the reload uses w_q and x_q directly, and int8 rounding flips on near-ties propagate through 36 layers x 4 passes; the loss is equal to 4 decimals (-0.004%), so quality parity holds, bit-parity does not.
- The naive reload is a trap: absmean of codes x s is s x (fraction of nonzero codes), not s, so the stock BitLinear re-rounds and the model loses half its quality: any deployment path must carry the scale or a pre-quantised flag.
- Byte accounting: embeddings and full-precision layers are 56% of the packed file; the ternary core would be 2.8 MB (1.8 MB at an ideal 1.58 bits). Whole-model compression at this size is 2.4x, not the 16x of the ternary layers alone, and bf16 for the rest would give about 12.1 MB (not measured). C9's ratios are therefore valid only for the ternary part. One checkpoint, one seed; descriptive.
