# E9: Unlooped control for E2

## Question and prediction
- **Question:** take E2's blocks (`[swa] [gdn, gdn, swa] [attn]`) and train them once, unshared and unlooped. Is weight sharing plus ~4 passes better than one pass of the same blocks?
- **Prediction (committed before running):** registry E9.prediction (commit `eecdaeb`).
  - Val loss 0.590–0.610, i.e. it beats E2 (0.619) with 41% of the FLOPs.
  - It assumed **lr 3e-3**. It's left unedited and scored as written.
  - The planned run uses E1's K7-tuned LR. That's stated in the registry notes and in `PREDICTIONS.md`, "Replication protocol".
- **Pass criteria:** `PREDICTIONS.md`, replication criterion 5:
  - looping helps if E9 − E2 > 2√2 × sd(E1);
  - looping hurts if E2 − E9 > 2√2 × sd(E1);
  - otherwise unresolved.

## How to run it
- Config: `configs/e9_unlooped.json` (12.31M total / 9.17M non-emb params, 0.079 train GFLOP/token, computed).
- Launch: in `experiments/launch/campaigns/phase2b-replication.campaign` as `E9 --seed 0 --lr <LR_E1>`. By hand: `bash experiments/launch/E9.sh --seed 0 --lr X [--dry-run]`.
- Compute: ~33 min, estimated (no clean throughput measurement yet; assumed ~5/6 of E1).

## Result (v0.4.79; card updated v0.4.107)
- RTX 5090 seed 0, lr 6e-3, 200M tokens (`experiments/checks/results/phase2b_5090.json`, `E9_s0`): clean80 bpc **0.2773**, against E2 seed 0 at **0.2845**. Looping the same 5 blocks costs 2.6% (one seed each, descriptive; C6). Val loss 0.6048 (contaminated val) is inside the registered 0.590-0.610.
- What E9 controls for: it has E2's 5 unique blocks, so it is the **parameter-matched** control (9.17M vs 9.46M non-embedding; E2 adds the inject projection). E2 applies the blocks 14 times and E9 once, so E9 is not FLOP-matched: E2 uses about 2.4x the FLOPs per token (0.193 vs 0.079 GFLOP). The first attempt (E9-20261122-152151-s0) was killed at step 600 and has no result.
