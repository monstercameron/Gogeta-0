## 2. Critique

1. **Overclaim against the ledger.** The README status line and "We know why" present the E1 win and the loop mechanism as settled. C5, C6 and C7 are PARTIAL and the drift reading (C59) is UNVERIFIED. AGENTS §0 says wording follows status, so the README should be fixed now, not after Q12.
2. **C18 is VERIFIED on a comparison that the project's own ledger weakens.** C44 shows the one-pass GDN arm swinging from 73.3% to 50.1% across seeds with identical init and data, yet the 81.5% vs 97.0% gap comes from single runs. The README pitch also omits that unshared depth (99.8%) beats the loop on the task that motivates the loop.
3. **Confound in E1 vs E0.** E1 changes five things at once: 5 of 6 attention layers become GDN, and it adds ShortConv, a SiLU output gate, out-norm and SWA-256 at T=1024. The "running notes" credit is not isolated. C76 and C77 are not tested here, and the SQ8 gate ablation is still `idea`.
4. **Compute is counted in FLOPs only.** SWA runs as a dense mask (C12 WRONG), and the hybrid is 2.1x slower than E0 in wall-clock (C122/C123, hardware-spark notes). "Cheaper layers" holds for FLOPs only, and the README should say so.
5. **The loop has no matched control, and the training gradient is truncated.** There is no unlooped control yet (E9) and no matched-FLOPs arm. `bptt_loops=4` with r ~ U{1..7} means loops 1..r-4 get no gradient (`n_nograd` in `model.py`). C33 says truncation lowers the value of a recurrence. The fix (SQ19, full vs truncated BPTT) is proposed but not in the queue.
6. **Regime mismatch [spec].** 200M tokens over 13.8M params is about 14.5 tokens per parameter, close to compute-optimal. The published loop wins (C67) come from over-trained regimes of about 2,000 tokens per parameter. Loops trade compute for parameters, so at this ratio E2's loss may be the expected outcome, not evidence against looping. This is untested here; the SQ33 regime sweep is the check.
7. **The "best at 4" story is in-distribution.** Training is r ~ U{1..7}, so r=5..7 are trained, and "worse beyond 4" is only fully supported where the loss curve is flat in-range. The README should report L(r) for r=1..7 on the checkpoint before saying "gets worse with more".
8. **Residual injection is unbounded.** `h = h + inject(...)` every loop with no contraction (`model.py`). K6 shows ||h|| growing 7.4 to 58.9, and C20 is REFUTED. This fits the instability literature (C31) and is a more direct cause than the coda-drowning hypothesis (C40).
9. **Seeds and data.** Headline claims need 3 seeds (AGENTS §5), and every LM result is single-seed. C93 (seed sd <= 0.004) is UNVERIFIED, so the noise yardstick is unknown. The val split is exact-dedup only (C107), and 32/164 HumanEval problems overlap training data (C103). K8, the leakage check, is queued at position 9.
