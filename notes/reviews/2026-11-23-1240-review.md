**2.4 Two code-read confounds in the FLOP and init accounting.**
- (code-read) `flops_per_token()` counts every loop pass at full 3x training cost, with no no-grad discount for the passes that run without backprop. v0.5.3 fixed the count in `train.py`, not here. If the FLOP-matching tables use this function, loop arms are mis-matched by about the 11% v0.5.3 found.
- (code-read) `effective_depth()`, which sets the residual init scale, uses `cfg.loops` (default 4), not the sampled r. For fixed-r arms this is consistent, but any arm with a different `loops` value gets a different init scale, and nothing records it as a variable.

**2.5 Scale and data bound the goal before compute does.** Every decisive result is a 14M-parameter model on 20M to 200M tokens. The README gives about 262M tokens for the Python subset, and v2 is about 200M used (SQ238). At the common rule of thumb of about 20 tokens per parameter (spec, general knowledge, not from the repo), a 1.2B model needs about 24B tokens, roughly 90 times the usable corpus (computed). The scaling-law plan (SQ291) waits on Stack v3, which needs a human download approval (SQ276). Goal 6 is data-limited before it is compute-limited.

## 4. The one experiment I would run next

**A matched-applications unique-parameter ladder at 20M, registered before A3.** Arms, all with 12 block applications and matched FLOPs:
- 3 unique blocks x 4 passes;
- 6 unique blocks x 2 passes (the A2 shape);
- 12 unique blocks x 1 pass (unshared).

Set each arm's `loops` to its real r, use fixed r (no sampling), and set `bptt_loops` to cover every pass, so sampling and truncation (v0.5.3) do not confound the arms. Three fresh seeds, two LRs per arm bracketing 6e-3 (the F2 choice), clean80. This merges 1215's shape arm with SQ350's 7x2 vs 14x1 pair, and adds the 3x4 arm, so it can be read as the C197 lever inside the loop family, or as the loop's cost at matched compute.

**Prerequisite:** I3, the FLOP-counter audit (CPU, minutes), so the matched labels are right.

**Why this one.** It is the cheapest test of the central question: does sharing cost anything beyond unique parameters at matched compute? If 6x2 ties 12x1 within 1%, reuse is free and the lever is the number of applications, which contradicts the C197 reading. If 3x4 and 6x2 both trail 12x1 by about C197's 7%, unique parameters drive the result and looping is a parameter-saving device. A3 is planned at 200M, so this 20M screen should set its shape arm. Cost (spec): 18 runs, roughly 1.5 GPU-hours on the N1X, from the queue's E1 throughput (about 100k tokens/s).
