# SQ382: per-pass MoE routing audit on A3m / A3mx

**Status:** done (descriptive, not registered) · **Verdict:** routing is substantially but not fully repeated across the two passes: top-1 expert agreement for the same token and block is 0.733 (A3m) and 0.712 (A3mx) against a chance level of 0.250, top-2 set overlap 0.81 / 0.80, so the shared experts are NOT used identically at every pass (far below the 0.9 level at which "unique parameters only" would be the reading) and not independently either · **Links:** script `experiments/checks/sq382_moe_routing_audit.py`, results `experiments/checks/results/sq382.json`

## Method
All 200M-token A3m (seeds 5, 6, 7) and A3mx (seeds 5, 6, 7) checkpoints on the fleet pulls (4 experts, top-2, ternary experts, MoE only in the 6-block looped core, loops = 2). Inference only (fp32 CPU) on 32 fixed sequences x 512 tokens (clean80 val docs concatenated; same for every model); the router's top-2 expert choices are recorded at each call (6 core MoE modules x 2 passes). Statistics: expert load per pass (share of the N x k assignments), agreement of the top-1 expert and overlap of the top-2 sets between pass 1 and pass 2 for the same token and same block (each pass's router sees a different hidden state), chance level for top-1 agreement = sum_e f_e(1) f_e(2) from the observed loads, and top-1 agreement between adjacent blocks in the same pass.

## Result (n = 3 seeds each; mean over blocks)
| arm | top-1 agreement pass 1 -> 2 | chance | top-2 overlap | max expert share (any block, pass) | adjacent-block top-1 agreement |
|---|---|---|---|---|---|
| A3m | 0.733 (sd 0.015; per seed 0.720, 0.749, 0.729) | 0.250 | 0.811 (sd 0.010) | 0.265-0.274 | 0.237 |
| A3mx | 0.712 (sd 0.005; 0.710, 0.717, 0.707) | 0.250 | 0.803 (sd 0.003) | 0.269-0.276 | 0.23-0.25 |
Load is almost perfectly balanced (max share 0.25-0.28 against 0.25 uniform) in both passes and all blocks; the entropy of the load is about 2 bits.

## Reading and caveats
- The reading rule from the review (agreement across passes > 0.9 means the rescue is unique-parameter count only) is not met: 27-29% of tokens switch their top-1 expert from pass 1 to pass 2, so passes do use the experts differently, i.e. some per-pass specialisation exists; it is far from random (3x chance).
- Adjacent blocks route about as randomly as chance (0.23-0.28), so agreement across passes is block-specific rather than a global token property.
- Only 2 passes exist in A3 (loops = 2, not 4), so no pass-to-pass trend can be resolved; the router sees hidden states that differ between passes, so agreement < 1 partly reflects state change, not "specialisation" in a causal sense (no ablation of routing was done). n = 3 seeds, one sample of 16k tokens.
