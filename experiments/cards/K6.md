# K6: does E2's loop converge?

## Question and prediction
- **Question:** does each pass of E2's looped core refine h toward a fixed point?
- **Prediction (committed before running):** `experiments/checks/PREDICTIONS.md`, section "K6", commit `f1b4ebd`. Not convergent: the relative change stays > 0.1 out to k=12, the norm keeps growing, and loss is lowest near k=4.
- **Pass criterion:** C20 is VERIFIED only if the relative change is non-increasing for k ≥ 4 **and** < 0.05 at k=12. Otherwise it is REFUTED for E2.

## How to run it
- `wsl -d Ubuntu-24.04 -- bash -c "cd /mnt/c/Users/mreca/Desktop/Gogeta-0 && ~/.venvs/gogeta/bin/python experiments/checks/k6_loop_convergence.py"`
- GPU, about 10 s. Script uncommitted at run time, HEAD `f1b4ebd`.

## Runs
Checkpoint `~/fusiondance-data/checkpoints/E2-20261122-132340-s0/model.pt`, eval mode, no_grad, bf16 autocast. Inputs: the first 16 non-overlapping 1024-token windows of `code-py-v1/val.bin` (+1 token for targets). h₀ = prelude output. Each loop applies `h += inject([norm(h), norm(e)])` and then the core. Norms are Frobenius over the whole [16, 1024, d] tensor. Per-token means are also stored.

## Results
| k | rel change | ‖h_k‖/‖h₀‖ | loss after coda |
|---|---|---|---|
| 1 | 7.197 | 7.42 | 0.7839 |
| 2 | 0.755 | 12.66 | 0.7339 |
| 3 | 0.409 | 17.60 | 0.7238 |
| **4** | 0.283 | 22.39 | **0.7224** |
| 6 | 0.177 | 31.71 | 0.7279 |
| 8 | 0.129 | 40.85 | 0.7373 |
| 10 | 0.102 | 49.89 | 0.7484 |
| 12 | 0.085 | 58.86 | 0.7598 |

- The relative change is non-increasing for k ≥ 4 (true), but 0.085 at k=12 is not < 0.05. **C20:** `REFUTED` for E2.
- Sanity check: the replica loss at k=4 equals `model.forward(loops=4)` exactly (0.72238).
- Computed from the table: the absolute step ‖h_k − h_{k−1}‖ ≈ 4.6–5 × ‖h₀‖ per loop is roughly constant. The relative change falls only because ‖h‖ grows linearly, so this is drift, not convergence.
