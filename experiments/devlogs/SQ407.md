# SQ407: scorer invariance for ternary arms (doc order, batch size 1 vs 8)

**Status:** done (descriptive; no prediction registered; thresholds from the row; CPU fp32 half only, the GPU bf16 half was not run) · **Verdict:** document order has no effect at all (per-doc NLL bit-identical across sorted, reversed and shuffled at batch size 1), and batch size 8 vs 1 changes per-doc NLL only in rare docs: the worst relative change is 7.1e-5 for A2s (ternary), 1.6e-7 for A2f (full precision) and 5.0e-4 for E27 (ternary fusion). The 1e-4 per-doc threshold is exceeded for E27 only, in a handful of docs (median change exactly 0); the A2s-vs-E27 contrast moves by 1.0e-4 log-points across all six configurations (threshold 0.1) · **Links:** script `experiments/checks/sq407_scorer_invariance.py`, results `experiments/checks/results/sq407.json`

## Method
The first 200 docs of the SQ339 300-doc clean80 subset, scored with the K8 protocol (window 1024, stride 512) in fp32 on CPU (GDN via the chunkwise torch kernel) for A2s, A2f and E27, seed 2 each, in 6 configurations: order sorted by length / reversed / shuffled (seed 0) x batch size 1 / 8, a batch being k consecutive window-chunks in that order, right-padded. Reference: sorted, batch 1. Reported: per-doc relative NLL difference vs the reference, aggregate bits/char, and the log-ratio contrasts A2s-E27 and A2s-A2f per configuration.

## Result
| model | aggregate bits/char (all 6 configs) | max per-doc relative difference vs ref (bs 8; bs 1 other orders = 0) | median | > 1e-4? |
|---|---|---|---|---|
| A2s | 0.290934 | 7.1e-5 | 0 | no |
| A2f | 0.269979 | 1.6e-7 | 0 | no |
| E27 | 0.348956 | 4.97e-4 (shuffled/sorted bs 8), 8.7e-5 (reversed bs 8) | 0 | yes (some docs) |
A2s-vs-E27 contrast, log-points: -18.18505 at bs 1 (all orders), -18.18495 to -18.18500 at bs 8: range 0.0001 points. A2s-vs-A2f range 0.00009 points.

## Reading and caveats
- Per the row's rule ("per-doc NLL moves by more than 1e-4 relative OR the contrast by more than 0.1 points -> pin batch size and order"), the per-doc condition fires for E27 at bs 8 and the contrast condition does not. Aggregate scores and contrasts are invariant to six decimals, so no published number changes; per-doc analyses that need bit-reproducible NLL (paired per-doc bootstrap across arms) should be run at a fixed batch size, and an order change by itself is safe.
- The ternary effect is real but small: relative float noise of ternary arms (7e-5, 5e-4) is 400-3000x that of the full-precision twin (1.6e-7), consistent with int8 rounding flips on near-ties when the padded batch shape changes matmul blocking. One seed, 200 docs, CPU fp32 only (the GPU bf16 path, the bigger noise source, is untested here).
