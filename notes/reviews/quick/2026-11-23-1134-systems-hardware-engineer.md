## Triage
- Per-box throughput benchmark: rejected as a separate run, accepted as a reading rule. Box speed cannot affect the A1 decision metric (on identical RTX 5090s, clean80 bpc depends on the host only through floating-point nondeterminism, which the A1z placebo measures; speed affects timing only). It can affect the throughput column. That column will be read within boxes, since every box ran two different arms, and each arm's tokens/s is reported with the box it ran on. A 16 GPU-minute benchmark would duplicate what the jobs already record (`tokens_per_s` in every run summary).
- Question (are arms and seeds balanced across boxes?): partly. The 16 original jobs were spread so that each box ran two different arms and an arm's two seeds ran on different boxes, so no arm is tied to one host. It is not a full balance: arms and boxes are not crossed, and the amendment jobs (A1i, A1z, A1k, plus the orphaned A1f-s0 and A1b-s0) go to whichever boxes finish first. The placebo A1z re-runs E27 on these hosts, which covers the host/code drift question for bpc. Throughput is read within boxes.
