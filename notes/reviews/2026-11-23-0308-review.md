## 2. Critique

### 2a. Architecture (gogeta/model.py)

1. **Recurrence precision is untested in our loss numbers.** The GDN gates are computed in fp32, but q/k/v are cast to bf16 and the kernel runs in bf16 on CUDA (model.py:209-213, code-read). The only precision check is C2: one-step error 3.96e-4 in bf16 vs 2.98e-8 in fp32 (ledger C2), a single-step test on random inputs. No LM loss has been scored in fp32. Every GDN-only lever (C197, C201, E11) rests on bf16 recurrence. SQ222 covers this at low priority, only for E1 vs E10, and cites model.py:~190; the cast is now at model.py:210-217.
2. **The random initialisation draws from the global RNG in module order.** `_init_weights` (model.py:274-284, code-read) and the default module construction both draw in sequence, so the same seed gives different weights for arms with different module shapes or order. Given that, the seed does not pair init across arms. (Inference from code-read; not run here.)

### 2b. Method

3. **"Paired" means paired on data only.** check_paired_batches.py (v0.4.100) confirms identical token batches per seed across arms. Init is not paired (item 2). So every paired CI (C5, C198, C199) pairs data and not init. The seed sd for E10 at d=256 is 7x E1's (0.0021 vs 0.0003, v0.4.87), which is what init noise would look like. (spec on the source; the variance split is not measured.)
4. **C201 reports one contrast on 5 of 8 cells.** The README describes a 2x2x2 factorial. The C201 scope lists only cells 000/001/010/100/111, and the 16 files from E23/E25/E26 ("other factorial cells") are excluded (v0.4.98 manifest). No pairwise contrast is reported, so the reading "penalties overlap" cannot be attributed to any pair.
5. **The scale of I is not stated, and it matters at the size of the effect.** Computed from the v0.4.97 cell means: on log bpc, I is about -0.033 (about -3.2% in ratio terms); on raw bpc, I = -0.019 bpc, which is -4.2% of the dense cell. The reported -3.5% (seed-blocked model) sits between the two, so C201 should name its scale.
6. **"Synergy" is a sign label, not a gain.** DEVLOG v0.4.97 says it means overlapping penalties, and the full fusion is still 11% worse than dense. C201's wording should say "sub-additive penalties" so the word cannot be read as a benefit.
7. **REFUTED covers two different things.** C5 is REFUTED with a point estimate of -0.18% and a CI that spans zero. The status rule is applied correctly and is qualified in the ledger, but "no detected advantage" and "evidence of no advantage" share one label. Proposal (spec, for the ledger vocabulary, not a change made here): a status such as NOT SUPPORTED for registered rules that fail on a CI spanning zero.
8. **Lever claims are in-corpus, FLOPs-matched bpc.** C197, C198 and C201 all measure clean80 bpc on code-py at matched FLOPs. Wall-clock differs by 1.6x for the GDN cell (v0.4.98). The README's "lever" sentence does not say either limit.

## 3. Alternative ideas (all speculation, labelled spec)

**A. GDN memory horizon from learned decay (weights only).**
- Hypothesis: most learned GDN heads have half-lives under 256 tokens, so the recurrent state acts as a local mixer and C18/C43's long-memory reading needs qualifying.
- Cheapest test: per head, half-life = ln(0.5) / ln(mean exp(g)) over 1k val tokens, on the E1, E11 and E32 checkpoints. One forward pass, CPU about 3 min (estimate).
- Changes plans: if over half the heads exceed a 1,024-token half-life, the state is long-range and C18 stands. If most are under 256, the linear-time memory story is local, and the next step is a decay-floor ablation.
- Novelty: SQ51 and SQ235 touch decay, but no queued check measures the learned horizon on existing checkpoints.

**B. Dynamic evaluation (per-document online adaptation).**
- Hypothesis: E10's gap to E1 shrinks under online updates if the hybrid's edge is partly in-context adaptation rather than stored knowledge.
- Cheapest test: the 330 SQ99 docs, weights reset per document, one small Adam step per 64 tokens, E1 vs E10 seed 0. CPU about 15 min at 14M (estimate). The protocol must not leak between documents.
- Changes plans: a gap shrink above half would mean the edge is in-context adaptation, which reframes C193 and the state-tracking story. No change means the edge is stored in weights.
- Novelty: no dynamic or online-adaptation item in side-quests or the queue (grep).

**C. Variance decomposition for the d=256 gap (init vs data).**
- Hypothesis: most of E10's extra seed variance at d=256 comes from init, because init draws differ across arms (item 2).
- Cheapest test: a 2x2 of init seed x data seed on E1 and E10 at 20M, 2 seeds each: 8 runs, about 15-20 GPU-min with compile (estimate). It needs a separate `--init-seed` flag, which is a small code change with its own tagged version.
- Changes plans: if init dominates, switch to shape-matched init (shared draws for shared tensors) before adding seeds. If data dominates, the paired design is right and C198 is a small-n problem.
- Novelty: SQ307 added fresh seeds, but no variance-source split is queued.

**D. Full 2^3 reanalysis of committed F2 scores (CPU, computed).**
- Hypothesis: the -3.5% interaction is carried by one pair of ingredients, not spread across all three.
- Cheapest test: compute every 2^3 contrast from the 250 committed per-run score files. CPU under 10 min (estimate).
- Changes plans: if one pair carries it, C201 narrows to that pair and the "fusion" reading weakens. If it is spread, the single-contrast reading holds.
- Novelty: SQ322 (TOST) and SQ328 (LR columns) do not cover pairwise contrasts. F2 is already unblinded (v0.4.97), so label the result exploratory.

**E. Mechanistic probe for variable bindings at distance.**
- Hypothesis: GDN layers carry a variable's bound value beyond the 256-token window, and SWA and attention layers do not.
- Cheapest test: synthetic snippets with one reassignment at distance 64, 256, 512 and 900, and linear probes on frozen per-layer hidden states of E1. About 10 min including 2k snippets (estimate).
- Changes plans: probe accuracy above chance at distance 512+ for GDN layers only would support a state mechanism for C18/C43 on code. Chance-level accuracy would mean C18/C43 do not transfer to bindings, and the state-tracking thesis needs a different test.
- Novelty: SQ90 and SQ63 test behaviour, not hidden states. No probe is queued.

**F. Fp32 recurrence check (promote SQ222).**
- Hypothesis: the bf16 recurrence changes clean80 bpc by less than 0.2%.
- Cheapest test: score E1 and E10 on the 330 SQ99 docs with fp32 and bf16 recurrence. Inference, about 3 GPU-min or CPU (estimate).
- Changes plans: a shift above 0.5% means C5, C197 and C201 are re-scored in fp32 before more claims. Near zero closes the concern.
- Novelty: exists as SQ222 at low priority. I would promote it, because the GDN-only lever claims have no check at all.
