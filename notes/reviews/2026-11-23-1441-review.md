## 2. Critique

**2.1 "Matched FLOPs" is wrong for the headline.** DEVLOG v0.5.10 says "the A1 winners add up to -16.7% at matched FLOPs" (quoted, line 278). The README glossary defines matched FLOPs as equal analytic training FLOPs per token (quoted, README line 171). C209 says A2s uses about 10% more compute. The confound favours E27, so compute-matching would shrink the advantage. DEVLOG v0.5.13 puts removing the truncation at about 2% (quoted), so the realistic shrink is a few points (computed, rough: 17% to about 14-15%). Fix it with an erratum in the next version, and check the README wording.

**2.2 The LR brackets are one-sided.** The amendment brackets A2s and A3mx only (quoted, v0.5.18 and v0.5.20). A2f, the full-precision reference for the +9.5% ternary cost (C207), is not in it. The ternary cost is fair only if A2f's optimum is also bracketed. The half-finished bracket already moves the A3mx-vs-A2s gap: at 3e-3, A3mx is 0.6% worse and A2s 0.6% better than at 6e-3 (quoted). That shifts the gap by about 1.2 points (computed), about 15% of the -7.67% headline. Small, but the same size as the C206 effect.

**2.3 A late-ternary schedule was already tested, and it was null.** A1f uses ternary_start_frac 0.5 (quoted, staged-configs/a1/a1f.json; code-read train.py:332-333). It gives -0.1% and +0.1% at two seeds (quoted, DEVLOG v0.5.13: "A1b, A1f null confirmed"). So the ternary cost is not a QAT-timing artifact at a 50% switch. Any ramp idea needs to beat that null first.

**2.4 The long-context protocol must name its RoPE table.** Rotary builds cos/sin to cfg.max_seq_len (code-read, model.py:153-155, :292) and forward slices it to T (code-read, model.py:158). So an eval beyond 1,024 needs max_seq_len raised. SQ392 interpolates the table itself, so it must state the max_seq_len used, or the baseline and interpolated arms may differ by an unrecorded setting (spec: this may already be stated; I could not check the SQ351 config).

**2.5 A4's metric is not the other arms' metric.** C210's verdict uses in-training v2 val, not clean80 (quoted). EOT contributes 0.072 nats of the 14% gap, and without it A4a is still about +7% (quoted). Whether the byte decoder is penalised for predicting the end of a token in its own step is a metric question (spec). Until SQ387 scores clean80, the 14% is a claim about this metric.

**2.6 The assembly claims are in-corpus.** Every assembly claim (C206-C212) is on code-py-v2 clean80 or in-training val (quoted). The only out-of-corpus test (C192) is refuted and covers E1 vs E0 only. Agree with the 14:09 review that this is the biggest validity gap. SQ379 is still an idea.
