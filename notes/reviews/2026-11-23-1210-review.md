## 2. Critique: the assembly plan and the method

**What is well designed (credit).** One change from E27 per arm; paired by seed, with data order verified to be shared (v0.4.100, `check_paired_batches.py`); predictions and the decision rule written before dispatch; "A1 changes no claim status" stated. The paired-seed structure is the right one.

**Confounds in A1 (code-read + computed).**

1. **A1a is not a single change.** E27 samples r ~ U{1..7} with `bptt_loops = 4`, and `model.py:338` runs the first `r - 4` passes under `no_grad` whenever r > 4. Fixed r = 4 (A1a) removes that truncation for the r = 5..7 batches, so A1a changes the gradient path as well as the depth distribution. The A1a prediction (-1.5%) cannot be attributed. A1h (r up to 5) has the same issue, smaller.
2. **A1g and A1h change unique parameters, which is the known lever.** A1g has 15.1M vs 9.5M non-embedding parameters (+59%) at the same 14 applications. C197 says unique parameters at matched FLOPs are what helps, and its unshared effect is about -7%. A1g is predicted at only -2%. If A1g wins, it confirms C197 inside the fusion and says nothing about a compensation. Report A1g and A1h as parameter-changed arms, not as winners of a compensation.
3. **Ternary arms share one LR.** E27 and A1d-f run at 6e-3, the LR of the 111 cell. QUEUE E3 notes say ternary "may prefer a different LR". A1d-f effects are therefore LR-conditional. At least a short LR grid on E27 and A1e is needed before a ternary arm is called a winner or a loser.
4. **The winner rule is weak and uncorrected (computed).** Per-seed clean80 sd for E27 is about 0.55% (the three values 0.3303, 0.3268, 0.3288 in PREDICTIONS). A paired two-seed mean then has sd about 0.55%, so the threshold of -1.0% is about 1.8 sd, one-sided p about 0.035 per null arm. With eight arms and independence, the chance that at least one null arm passes is about 20-25%. The "about 2 seed sd" wording overstates the margin. The "both seeds same way" condition helps only a little.
5. **Winner's curse into A2.** Arms are selected on seeds 0-1 and then stacked in A2. If A2 reuses seeds 0-2, the stacked effect is inflated. A2 must use fresh seeds.
6. **Gap closed is not computed.** The prediction says no arm closes more than half the 30.8% gap, but the screen has no dense reference (E20 seeds 0-1 exist and would be the same-seed control). Add E20 to the A1 table so "% of gap closed" is a paired number.
7. **Efficiency is not in the decision rule.** The thesis is quality per FLOP and quality per wall-clock. SQ338 shows GDN loses at equal wall-clock. A1 reports tok/s but the winner rule ignores it. A winner that costs wall time should not be stacked silently.
8. **Missing compensation arms.**
   - The un-gated injection (model.py:342, 297) is attacked only by A1c, with a sigmoid per-channel gate at init 0.9. A1c is not a Jacobian bound: the core's residual blocks can re-grow h after the gate (code-read). SQ268 (closed-gate restart) and SQ329 (re-injection gain) are the stronger tests of the same mechanism and are not in the screen.
   - No teacher-distillation arm (SQ251 covers E1 from E10 only).
   - No loop-placement arm (SQ343 is not in the screen).

**Architectural blocker (code-read).** `gogeta/model.py:284-285` raises when `moe_experts > 0` and `ternary=True`. The best measured lever with a VERIFIED result (C203, MoE/wide FFN) therefore cannot be combined with the ternary ingredient in the current code. Any assembled model that keeps ternary cannot use the MoE or wide-FFN lever without a new code path (batched BitLinear experts).

**Over-claim: E60c is not an FLOP-matched arm (computed from the widths in v0.5.0).** E60a is top-2 of 4 x 512, so 1024 hidden units are active per token. E60c is a dense 2048 SwiGLU with the same total parameters, so its FFN matmuls cost about twice E60a's. v0.5.0 reads the result as "unique parameters in a plain FFN beat routed experts at about the same wall time", which is a parameter-matched comparison, not a compute-matched one. The near-equal wall time (5.19 vs 5.05 min) is a measured fact, but it suggests the MoE gather overhead offsets the FLOP difference rather than showing equal compute. C203 itself (E60a vs E1 at matched active FLOPs) is fine.

**What would make the assembled model competitive (spec).** The data so far favour unique parameters at fixed active compute (C197, C203, E32), and penalise loops and ternary as costs (C202, C6/C7). If that holds, a competitive assembled model is probably an unshared or MoE core with at most a loop that pays on the param-matched control (SQ350), and ternary only if it is cheap in quality. The current A1 bar is "recover part of E27's gap to dense E20". The bar that matters for the final-model plan is "match E32 (unshared, C197) at matched active FLOPs". A1 should report both references.

**Over-claimed or under-stated items.**
- The README and the site pitch the fusion as "three ingredients stack"; the ledger says they compound negatively at 200M (C202). That wording is correct in the ledger but the pitch should not stay as a headline.
- "Scale is the lever" is supported for unique parameters only, at 200M and 4 seeds (C197). It is not yet a scaling law; the final-model plan needs the fit to be labelled as a fit.

## 3. Alternative ideas (6)

**I1. Truncation control on the fused cell (added to A1 now).** (spec)
- Hypothesis: much of the loop/ternary penalty is the 4-pass BPTT truncation, which starves early loop passes of gradient once r > 4.
- Cheapest test: E27 with `bptt_loops = 7` (full backprop, otherwise identical) at 200M, seeds 0-1, paired with E27 (shared data order). One 200M run per seed. This is the arm that makes A1a interpretable; A1a should then be compared with this arm, not with E27.
- Changes plans: if bptt 7 moves E27 by at least 1% in the good direction, truncation is a first-order cause, and every loop cell in F2 is mis-trained at 200M; A2 must include it. If |effect| < 0.5%, truncation is excluded and A1a is a clean depth-distribution test.
- Novelty: SQ19 is full vs truncated BPTT on H0 only. Not run on the fused cell, and not in A1.

**I2. Placebo arm to measure the screen's false-positive rate.** (spec)
- Hypothesis: with two seeds and eight arms, at least one arm will look like a winner by chance.
- Cheapest test: a placebo arm that changes nothing observable (e.g. E27 with a no-op flag that is inert at init and at lr 0 for the new parameter), run on seeds 0-1 and scored with the A1 rule. Two runs.
- Changes plans: if the placebo passes the -1.0% rule, the screen threshold is too loose and every A1 winner needs a second stage on fresh seeds before stacking.
- Novelty: SQ94 and SQ224 are leave-one-seed checks on Phase 2b; no placebo arm for A1 is queued.

**I3. LR-matched ternary arms (ternary-specific).** (spec)
- Hypothesis: the +15.8% ternary penalty (C202 cell 001) is partly LR mismatch, because absmean STE gradients scale differently from full precision.
- Cheapest test: E27 and A1e at 20M tokens, LR {3e-3, 6e-3, 1.2e-2}, two seeds: 12 short runs.
- Changes plans: if the best ternary LR is off 6e-3 and closes more than 2 points, C202's ternary and interaction numbers need restating at matched LR, and A1d-f must be re-run at their own LR. If the optimum stays at 6e-3, the LR caveat is closed.
- Novelty: SQ339 splits the ternary factor post hoc and SQ342 completes LR for the dense and GDN cells at 200M, not ternary. Ternary LR is not queued.

**I4. Distillation from the dense 200M checkpoint (optimisation vs capacity).** (spec)
- Hypothesis: the fused cell fails partly because it cannot fit what the dense model fits in the same tokens (an optimisation gap). Teacher KL from the dense checkpoint should close part of the gap if so, and none if the gap is capacity.
- Cheapest test: E27 at 20M, two seeds, KL to E20's logits at lambda 0.5 (teacher forward adds compute; report it). E20 checkpoint is on disk (SQ342 lists E20).
- Changes plans: if the 111-vs-dense gap closes by at least half at 20M, the problem is optimisation and the E61 recipe should include distillation. If not, the fusion needs an architecture change.
- Novelty: SQ251 distils E10 into E1 only. The fused-cell version is not queued.

**I5. Per-pass low-rank adapters on the shared core (per-pass parameters without unshared depth).** (spec, speculative)
- Hypothesis: the loop penalty comes from tying the weights across passes. Per-pass rank-8 adapters (zero-init B) on the core give each pass some unique capacity at a few percent extra parameters, and keep the loop's compute.
- Cheapest test: 20M, two seeds, cell 111 with per-pass adapters vs cell 111 plain vs the 14-unshared control (E32 config at 20M). CPU is too slow; one short GPU run per arm.
- Changes plans: if the adapter arm closes most of the gap to the unshared control at under 5% extra parameters, loops become a viable parameter-saving device and E61 keeps them. If not, loops are pure compute cost and E61 drops them.
- Novelty: A1b is a per-pass bias vector only. Mixture-of-Recursions and relaxed-recursive ideas are in refs/ (I did not check whether any are queued). Treat as related, not identical.

**I6. Ternary experts for the MoE lever.** (spec, needs code)
- Hypothesis: C203's unique-parameter gain survives if the experts are ternary, so the assembled model could keep both levers without the ternary guard at model.py:284-285 blocking them.
- Cheapest test: a code path with BitLinear experts (moe.py), then E60a-shape at 20M, two seeds, against dense-ternary at matched active FLOPs. CPU smoke test first.
- Changes plans: if ternary experts keep the MoE gain within about 1 point, the assembly can use MoE. If the gain disappears, the assembly cannot combine ternary with the lever that works.
- Novelty: SQ256, SQ257 and SQ260 vary the MoE router or host. None combines ternary experts. Code is a precondition.

## 4. The one experiment I would run next

**Add A1i to the screen before dispatch, and read A1a against it: E27 with `bptt_loops = 7`, 200M tokens, seeds 0-1, paired with E27.** (spec)

- Why: A1a's effect cannot be read as a compensation until the truncation confound is measured (section 2, item 1). The arm is one config change, reuses the E27 data order and the SQ263 reference, and is the only candidate that could explain the anti-synergy by a training-procedure cause rather than an architecture cause.
- Prediction (spec, to register before running): A1i moves E27 by at least -1% on the clean80 metric at 200M (the truncated gradient is the cause of part of the loop/ternary penalty). Falsifier: |effect| < 0.5% on both seeds, which would exclude truncation as a first-order cause and make A1a a clean depth-distribution test.
- Caveat (spec): at 20M the F2 interaction was favourable (C201), and SQ337 shows it grows through training, so a 20M test could miss the mechanism. The test must run at 200M.
- Cost: two 200M runs, inside the A1 budget cap. No new code.
