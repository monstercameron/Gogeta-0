## 2. Critique

**Architecture and scoring (code reading):**

1. **The reversal sits on the scorer's chunking boundary.** sq_99 scores any document longer than its 1,024-token WINDOW in 1,024-token windows with stride 512 (sq_99 lines 71, 376-400). Each window is fed from its own start, so the recurrent state begins empty there. Both models lose everything before a window start, but only GDN's state is built to carry long-range information. Nearly every document in the >1,200 bin is chunked, and the bin where the gap turns positive starts where chunking starts. C193's "long-context" reading is therefore confounded with the scorer. Not run; the unchunked 600-1,024 bin is the test (idea A).
2. **Training and doc-level scoring disagree about document boundaries.** tools/prepare_data.py writes `<|eos|>` after every document into one stream, and model.py has no document mask or state reset (GDN forward model.py:183-199; attention model.py:132-141). In training, GDN state carries across documents; in doc-level scoring each document starts from an EOS-prefixed fresh state (sq_99 line 20). Attention is affected less, because its window is bounded. [spec] This could contribute to the packed-vs-doc-level gap; C101 covers the level of that gap, not its sign.
3. **Context is capped at 1,024.** ModelConfig `max_seq_len=1024` (model.py:52), and Rotary slices `[:T]`, so longer inputs fail. Every long-context claim (C193's reading, SQ52, SQ214) is bounded at 1,024.
4. **The loop injection is an unscaled sum** (model.py:265, `h = h + inject(...)` each pass). The state norm grows with r (K6, C39). Loop fixes SQ15/16 act on this line, so the loop claims rest on it.
5. **The efficiency pitch rests on FLOPs, not time.** E1 has 0.94x E0's FLOPs but runs about 2.1x slower on our kernels (SQ77 text; C122/C123). The FLOP model counts GDN as `4*H*hd^2` per token (model.py:309), which leaves out chunk-kernel overhead. README line 125 ("the cheaper layers win ... at slightly less compute") leans on the FLOP count.
6. **Window arms are compute-identical by construction** (dense boolean-mask SWA, model.py:124-140). Fine for SQ214's matched-compute design, but it means no speed claim about SWA is possible before SQ72.

**Method:**

7. **"Tuned" means one axis, one seed, 20M tokens, contaminated val.** K7 varies LR only (QUEUE, K7 row). Warmup, weight decay, schedule and the GDN decay/write init are all fixed. Whether C92's LR transfers to 200M is untested.
8. **Seed noise is thinly measured.** E10's three seeds give a sample sd of 0.0020 absolute, about 0.34% relative (computed). With 2 degrees of freedom, the 95% interval for sigma runs from about 0.001 to 0.013 (computed, chi-square). E1 has one seed at its tuned LR, so the 3.6% headline is not a statement about seed variance.
9. **SQ214's tolerances sit inside its own noise.** With two seeds per arm, the 95% half-width on a difference is about +/-1.5% if sigma is about 0.34% (t with 2 df; computed). W1 asks for <=1.0%. The "2x seed spread" rule takes one difference, |s0 - s1|, as its spread estimate. The noise at 20M tokens is not measured (SQ96 quotes E1 at 0.9925 with no sd).
10. **E14's +/-0.5% equivalence needs about 8 seeds per arm** (TOST, sigma about 0.34%, 80% power; computed roughly). Three seeds, as in SQ216's plan, will not show equivalence. E14's unshared control also has about 2x the parameters (reviewer 20:37, item 9), so the parameter confound remains.
11. **The confirmatory set is not the unused one.** Phase 2b verdicts use clean80, a subset chosen by a near-dup threshold (20:37 review, item 3). The frozen test split has no registered comparison yet.
12. **Over-claimed wording.** README line 121 bolds "-3.6%" in the results table with no C5 PARTIAL tag, while line 47 carries one. AGENTS §0 allows fact wording only for VERIFIED claims. Also, the 3090 reproduction tests that the same code is deterministic. It says nothing about seed noise.
13. **Multiplicity.** The length analysis has four bins, a pooled test and several protocol variants, with no correction. Only the >1,200 bin's CI excludes zero.

## 3. Alternative ideas

Each idea gives a hypothesis, the cheapest test, what would change our plans, and novelty.

**A. Reset-matched scoring control** (the test for critique 1). [spec] Hypothesis: the >1,200 reversal comes from the 1,024/512 chunking, not from length.
- Test: CPU, the E0 and E1 seed-0 checkpoints, the sq_99 scorer. (i) Score unchunked documents of 600-800 and 800-1,024 tokens. (ii) Force chunking (window 512, stride 256) on the <=1,024-token documents and recompute the gap. About 25 CPU-min (SQ99 took 26).
- Changes plans: if forced chunking reproduces most of the >1,200 reversal, C193 becomes a scorer artifact, and SQ214's primary metric must be checked for the same chunking before any window claim. If not, the reversal is real and still unexplained.
- Novelty: not in side-quests or the queue. SQ203 bins in-corpus clean80 by token distance.

**B. Document-boundary carry-over test.** [spec] Hypothesis: E1's doc-level advantage depends on whether GDN state starts fresh or inherits the previous document's tail; E0 is indifferent.
- Test: CPU, clean80 and out-of-corpus documents, E0 and E1 seed 0: (a) EOS-prefixed fresh (current); (b) prefixed by a random other document (packed-like carry-over); (c) packed 1,024-token windows. About 15 CPU-min.
- Changes plans: an E1 sign change between (a) and (b) that E0 lacks would make the scoring protocol part of the headline. A fair hybrid comparison would then need a state reset at EOS (fla varlen, SQ185) in training.
- Novelty: 20:37 I1 asks whether the sign flips across protocols; this proposes a mechanism and a training-side fix. SQ185 is kernel correctness only.

**C. In-document repetition as the covariate, not length.** [spec] Hypothesis: the out-of-corpus gap tracks the share of a document's tokens that repeat an earlier in-document n-gram; length is a proxy, since long files repeat more.
- Test: CPU, the saved per-document NLL from sq_99. Compute the 8-gram repeat share per document and regress the E1-E0 difference on log length and repeat share jointly, with a package-clustered bootstrap. About 10 CPU-min.
- Changes plans: if repetition absorbs length, SQ214's window sweep tests the wrong mechanism. Copy structure becomes the target, which fits the thesis's "running notes" story.
- Novelty: SQ203 uses token distance on in-corpus clean80. SQ214 and C193 assume length. I have not seen a joint covariate test.

**D. Schedule robustness of the ranking.** [spec] Hypothesis: the E1-vs-E10 order at 20M tokens flips under a different schedule (constant-then-decay vs cosine).
- Test: E1 and E10 at 20M tokens under two schedules, seed 0, on one rented card: four runs. At the SQ220 throughput (E1 254k tok/s on the 3090), 20M tokens is about 80 s before compile (computed).
- Changes plans: a flip means the K7 tuning and any 200M ranking inherit a schedule assumption. Stability makes C5's direction more trustworthy.
- Novelty: K7 varies LR only. SQ11 (Muon) and SQ12 (LR stress) do not vary the schedule.

**E. Seed count at 20M, now affordable.** At about 80-100 s per E1 run on a 3090 (computed), 8 seeds per arm for SQ214's three windows plus E10 and E1 at the default window is a few GPU-hours, spread over several rented cards.
- Hypothesis: 8 seeds pin sigma at 20M and make W1-W3 testable. [spec]
- Test: the SQ214 configs x 8 seeds, plus the default-window arms on the same seeds. Report sigma and its CI.
- Changes plans: if sigma at 20M is 0.5% or more, the 2-seed design is void and every 20M result needs n >= 8. If it is 0.2% or less, the 1% tolerance in W1 means something.
- Novelty: a re-specification of SQ214, not a new arc. SQ216 (noise floor) should merge into it.

**F. The frozen test split as the confirmatory set for C5.** Hypothesis: the E1-vs-E10 comparison at 200M holds, or fails, on the 462-file frozen test split, with no tuning on it.
- Test: score the Phase 2b checkpoints there. About 1M tokens, minutes.
- Changes plans: the Q12 verdict moves to an unused set, and clean80 becomes a sensitivity check.
- Novelty: partly SQ218 (20:07 triage). I would make it the Phase 2b verdict set, not an extra run.
