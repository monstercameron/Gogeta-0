# SQ403: eval-time pass count on A2s (trained at r = 2)

**Status:** done (registered in PREDICTIONS.md section SQ403) · **Verdict:** r = 1 is 27.9% worse than r = 2 (95% CI +23.5 to +32.2%, n = 3), which meets "at least 5% worse" but lands above the registered range (+3% to +25%); r = 3 is 7.6% worse than r = 2 (CI +6.4 to +8.8%), which is NOT within the registered +-2% (range -1% to +4%): the model is sharply tuned to its trained pass count in both directions · **Links:** script `experiments/checks/sq403_eval_pass_count.py`, results `experiments/checks/results/sq403.json` (eval r recorded per row)

## Method
A2s 200M checkpoints (trained at fixed r = 2, loops_min = loops_max = 2), seeds 2, 3, 4. Clean80 doc-level bits/char on all 2,333 clean80 docs (K8 protocol, window 1024) with the CPU scorer of `sq339_cpu.py` (fp32, GDN via the chunkwise torch kernel; reproduces the GPU clean80 numbers to about 0.01%, SQ339 devlog), at eval loops r = 1, 2, 3 passed through the forward's `loops` argument. The `score_doclevel.py` GPU scorer itself was not used (no GPU).

Mean vs r = 2: r = 1 +27.88% (sd 1.75; t-CI +23.53 to +32.22, df 2); r = 3 +7.60% (sd 0.49; CI +6.37 to +8.83).

## Reading and caveats
- A large r = 1 gap shows the second pass is used; as registered, it does not show the pass beats unshared depth (a model trained at r = 2 and run at r = 1 is a distribution shift). The r = 3 deficit (+7.6%) is smaller than the r = 1 deficit but far from the "within 2%" prediction: unlike E22/E27, which were trained with r ~ U{1..7} and are flat around their default (SQ341), a fixed-r model is not robust to extra passes. The prediction's premise (SQ341/SQ348 "loss best at the trained r" implies flatness) did not transfer from variable-r training to fixed-r training.
- Per-seed spread is small (sd 0.5-1.8 points); n = 3 seeds; no other aspect of the model changes between eval r values.
