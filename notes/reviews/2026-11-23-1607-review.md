## 2. Critique

**2.1 C212 counts seeds that chose its arm (ledger text, computed).** C212 is "3 seeds, registered", but seeds 0-1 come from the exploratory A1 screen, which is where A1a was picked as a winner. Seeds 0-1 both selected the arm and tested it, so part of the -3.17% can be winner's curse. The one fresh seed (2) gives -3.11%, which suggests the bias is small here. The wording should say so, and the CI should not be read as a fresh-seed interval. C212 is also not LR-bracketed (its own limitation).

**2.2 The "loop cost" in D3 is also a unique-parameter deficit (code-read, computed).** A2f is a 6-block core run twice; E24 is 12 unshared blocks at the same FLOPs. So A2f has about half the core's unique parameters (model.py l.302-306; README F2 numbers: 12.3M vs 27.9M for the matched pair). The +3.2% (C204 P4, DEVLOG v0.5.28) therefore carries the C197 parameter lever as well as any loop effect. SQ350 is the parameter-matched control (7x2 vs 7x1 vs 14x1, 2 seeds, about 10 GPU-min), but it is still "idea (needs a GPU budget approval)". Since it is cheap and decides D3, it should be promoted, not left in the backlog.

**2.3 One untuned reference carries two headlines (quoted).** "The full fusion is 30.8% worse than dense" (F2 cell 111) and "the assembly beats the full fusion by 16.7%" (C209) both use the untuned E27. A1 shows that single fixes are worth 7.6% (fp ends, C205) and 3.2% (fixed r, C212). So most of the 16.7% is removal of defaults the project already knows are bad. That is a real result, but it should be stated as "tuned recipe vs untuned fusion" in the same sentence. Dense parity is point estimates only (no TOST), which the README says, but the pitch should not read as a tie.

**2.4 The long-context pillar mixes window and RoPE (quoted SQ351, code-read).** The dense arm sees RoPE positions beyond its training length. The hybrid's SWA layers only attend to relative distances below 256, so their RoPE angles stay in distribution. Only the coda is global. The -60.7% beyond 1,024 is therefore "windowed vs unwindowed RoPE" as much as "linear-time vs quadratic". Inside 512-1024 the GDN hybrid is 13% worse (SQ351, unexplained). (spec) That is what a copy-at-distance deficit (SQ347) would predict, and it suggests the advantage is a crossover, not extrapolation. SQ392 tests interpolation only; it does not separate window from global attention (see I-3).

**2.5 Matched-FLOP accounting favours attention-heavy arms in wall-clock (code-read, quoted).** SWA is counted at its window (model.py l.437) but runs as a dense T x T mask (l.8-9, l.203), and ternary is counted at full precision (quoted as a reading rule, v0.5.27). FLOP-matched contrasts that involve SWA therefore understate its wall-clock cost, and SQ338 shows the two accountings can disagree in sign (GDN is 1.62x dense wall time, so 8% worse at equal wall-clock). Every matched claim should say "per analytic FLOP" next to the number.

**2.6 The compounding reading rests on one horizon pair (quoted).** The interaction changes sign between 20M (-3.5%, C201) and 200M (+6.2%, C202). The 200M reading is the only evidence for "the penalties compound", and its LR coverage is incomplete (H2' FAIL). SQ342 is the right item, but it should be treated as blocking for any README wording that says "compound" as a finding rather than a PARTIAL.

## 3. Alternative ideas (speculation throughout; checked against side-quests.md by keyword)

**I-1. Pass identity without parameters (spec).**
- Hypothesis: part of the tied-vs-unshared gap is that tied passes are indistinguishable. A fixed, per-pass orthogonal conjugation (pass i computes R_i^T f(R_i h), zero parameters) gives each pass its own basis.
- Cheapest test: 20M tokens, 2 seeds, A2f-style shared 6x2 on clean80. Four arms: plain tie; conjugated passes; loop_embed (an existing switch, model.py l.77); unshared 12 (E24-style) as reference. About 8 runs, roughly 40 GPU-min.
- What would change plans: if conjugation closes at least a third of the 3.2% gap, pass identity is part of the loop cost, and a learned rotation (a few d^2 per pass, computed) is worth a run. If neither conjugation nor loop_embed closes anything, the penalty is capacity, and SQ350 decides D3.
- Novelty: loop_embed is an additive per-pass vector and SQ357 is per-pass low-rank adapters. A multiplicative, zero-parameter conjugation does not appear in side-quests.md (keyword search: rotation, conjugat, orthogonal; SQ6 is a state-update rotation, a different thing).

**I-2. Does the assembly gain need document structure? (spec).**
- Hypothesis: most of the 16.7% is within-line, local statistics, not long-range state. If so, the state-tracking motivation (goal 2) is not what the headline measures.
- Cheapest test: inference only, no training. Score A2s, E27, E24 and E20 on the clean80 docs with lines permuted inside each doc (seeded). CPU is enough at the SQ99 scale, about 40 CPU-min.
- What would change plans: if the gap keeps at least 80% under permutation, the headline is local, and goal 2 needs its own probe (SQ90). If it keeps 50% or less, the gain uses document-level structure, and the C213 story needs rewriting.
- Novelty: SQ203 bins by distance to the last occurrence of a token; it does not destroy structure. SQ90 is a probe, not a headline re-score.

**I-3. Window vs global attention at 2,048 (spec).**
- Hypothesis: the dense degradation past 1,024 (SQ351, +160%) comes from the global RoPE layer, so an SWA-only stack should stay flat.
- Cheapest test: eval only. Score E41 (the SWA-only stack, quoted in PREDICTIONS.md as "+1% to +4% vs E1") and E1/E10 on the SQ351 protocol at 2,048 tokens, CPU, about 10 CPU-min per arm.
- What would change plans: if SWA-only stays flat like GDN, the efficiency-pillar wording should say "windowed", not "linear-time". If SWA-only degrades like dense, the GDN state is what helps past the window.
- Novelty: SQ392 uses interpolation on the A-series dense checkpoints. E41 has not, as far as I found, been scored past 1,024.

**I-4. Ternary threshold sensitivity, shared vs unshared cores (spec).**
- Hypothesis: a shared ternary core flips more weights per pass, so its loss is more sensitive to the quantiser threshold than an unshared ternary core (SQ353's flip noise).
- Cheapest test: inference only. Scale the absmean threshold by 0.8, 0.9, 1.1 and 1.2 for A2s and an unshared ternary core at matched FLOPs (E27 or an equivalent). About 5 GPU-min.
- What would change plans: a sensitivity ratio of 2 or more means the ternary loop cost is a quantiser-decision effect. The next run is then a per-pass learned scale (12 scalars). A ratio near 1 means the cost is not in the decisions.
- Novelty: extends SQ353 (flip noise) and SQ378 (packing). No threshold sweep was found in side-quests.md.

**I-5. Is the fixed-r gain horizon-dependent? (spec).**
- Hypothesis: the 3.2% fixed-vs-random r effect (C212) is partly a 200M effect, like the C201 sign flip.
- Cheapest test: 20M tokens, fresh seeds 3-5, A1a vs A1i (6 runs, about 30 GPU-min). Fresh seeds also fix 2.1.
- What would change plans: if the effect is gone at 20M, C212 becomes a horizon claim, and random-r training stays in the recipe only if it helps at 200M.
- Novelty: C212 is 200M only. Low priority next to I-2 and I-3.
