The fighters

Three techniques, three different costs

Each one is strong on its own and has a known weak spot. The bet is that each weak spot is covered by one of the other two.

Attacks: context cost

Linear-time mixers

Gated DeltaNet / Mamba-style recurrent state plus sliding-window attention. By design, memory stays fixed-size instead of growing with every token (our current sliding-window kernel still uses a dense O(n²) mask).

Mixing cost (design)O(n²) → O(n)

Weak spot: limited multi-step state tracking per layer.
Covered by loops, which add depth.

Attacks: parameters

Looped depth

One shared block applied r times. Depth comes from compute instead of new weights, and harder inputs can get more passes.

Depth per weight× r

Weak spot: every pass costs compute.
Covered by ternary, which could make compute cheap with real ternary kernels (ours only simulate it, so no speedup yet).

Attacks: bits

Ternary weights

BitNet b1.58: every weight is −1, 0 or +1. About 1.58 bits each. With dedicated ternary kernels, matrix multiplies could turn into additions; our code only simulates the rounding, so for now it is slower, not faster.

Bits per weight16 → 1.58

Weak spot: rounding error could compound across loops.
Countered by per-loop norms and input re-injection. We'll measure it.

The fusion

The FusionDance architecture

A small, unshared prelude and coda around one shared core block that loops. v0 layout:

The one rule

Nothing quadratic lives inside the loop (by design). Anything inside the loop runs r times, so the only full-attention layer sits outside it and runs once. Today's sliding-window kernel still uses a dense mask, so it is O(n²) until a block-sparse kernel replaces it.

  • Gated DeltaNet: linear-time mixing with a fixed-size memory that can overwrite, not just add, which gives better recall than plain linear attention.
  • Sliding-window attention: exact attention over the last ~256 tokens for local precision. O(n·w) in principle; our current kernel uses a dense mask, so it is still O(n²).
  • The loop: the same weights run r times. Training samples random r; at inference you choose how hard to think.
  • Exit head: a cheap readout after every pass. It drives per-loop training, the critic, early stopping and self-speculative drafts.
  • Coda: a single full-attention layer for exact long-range recall. It's the only part whose memory grows with context.

Main quest

Byte Quest: granularity × loops

Bytes are a main quest now. Design concept, not a trained model: every number on this page is an estimate from the design note, and experiments E12–E16 are planned, not run.

The idea

Depth where the information is, iteration where the errors are. The heavy E1-style stack runs once, on patches of P bytes. A small shared-weight block then loops r times at byte resolution to fix spelling, digits and syntax.

  • Why bytes: no tokenizer, exact characters, robustness to odd spellings, and a 256-way head instead of an 8,192-way one.
  • Causality: global states are shifted by one patch, so a byte never sees its own patch's summary.
  • Estimated cost at P = 4: about 1.04× / 1.19× / 1.48× E1 for r = 1 / 2 / 4 (a flat byte model would be about 3.6×).
  • Honest caveat: the literature says bytes trail BPE below roughly 4B parameters on code. The claims here are about granularity and loops, not beating BPE-E1.

The science

Three budgets, measured separately

n = context length, L = layers, r = loop count, S = fixed recurrent-state size. At laptop scale the absolute megabytes are tiny, so the result we care about is how each cost scales. The FusionDance column is the design target: our sliding-window layers still use a dense-mask kernel (O(n²)), and ternary weights are simulated in floating point.

Big ideas

What we're actually testing

These are the claims, stated so they can be shown wrong.

🌀

Think in loops, not out loud

Chain-of-thought reasons by writing tokens, and every token grows memory and attention cost. Latent loops reason silently. How much written reasoning can loops replace at matched compute?

⚔️

The Rival Loop

Agents improve code with a critique → fix cycle. We build that rivalry into the recurrence: every pass is scored, a critic head trained on the real loss decides when to stop, and adversarial damage-and-repair teaches loops to fix their own mistakes.

⚡

Instant transmission

A looped model can draft for itself: 1–2 passes guess the next few tokens, and the full loop count verifies them. Self-speculative decoding with no separate drafter.

📈

Scaling shape over raw numbers

Only one layer's memory grows with context, and nothing inside the loop is quadratic. We report curves (cost vs context, quality vs bits, quality vs loops), not single numbers.
