# SQ374: byte models E13a-d scored on clean80, matched-FLOPs comparison with token models, patch lag

**Status:** done (descriptive, not registered; n = 1 seed per byte run) · **Verdict:** at roughly equal training FLOPs the BLT-lite byte models are far worse than the token baseline on clean80 bits/char: E13b (P = 4, 200M bytes, 5.09e15 FLOPs) 0.553 vs E1 (53.5M tokens = the same text, 4.87e15 FLOPs) 0.339, +63%; E13a (P = 2, 9.19e15 FLOPs, 1.9x E1's) 0.462, +36%. Loss rises across the slots of a patch (patch lag) by 7-9% at 200M and 12-15% at 20M for P = 2-4 · **Links:** script `experiments/checks/sq374_byte_scoring.py`, results `experiments/checks/results/sq374.json`, flops `experiments/byte_model/flops-table.md`

## Method
Runs (fleet copy gogeta-cockpit-w4-1, seed 0): E13a/E13b at 200M bytes (lr 3e-3), the 20M-byte sweep E13a-d at lr 3e-3 (P = 2, 4, 8, 16) and the SQ188 LR grid of E13b at 20M bytes (lr 1.5e-3, 3e-3, 6e-3, 1.2e-2). Byte scorer = the K8 protocol in bytes: ids = [EOS] + utf-8 bytes, window 4,096 (the training length), stride 2,048 for the few longer docs, targets = the doc's own bytes, bits/char = total NLL in bits / characters, on the 2,333 clean80 docs (K9 overlap < 0.8; 2,670,035 bytes). fp32 CPU; byte_model code with the GDN kernel replaced by the chunkwise torch kernel of `sq339_cpu.py`. The scorer's all-val-equivalent check: train-time `val_bits_per_char` (all val docs, last pass) and my clean80 differ by -0.8% to +16% (clean80 is harder than all-val by construction: 200M E13a 0.462 vs 0.401), so only the ordering is a check, and the 20M runs, where memorisation is small, agree within 0.8-1% (E13b lr 3e-3: 3.931 vs 3.919). Train FLOPs of a run = `flops_per_token_at_default_loops` (bytes) x budget, from each run's meta; token runs = every fleet score file with a local meta (515 runs).
Patch lag: NLL of target bytes grouped by slot = (position in window) mod P (windows start on patch boundaries; slot 0 is predicted from previous patches only).

## Reading and caveats
- The 20M-byte runs (5.0M-token equivalents) are far from converged (3.3-4.4 bits/char) so the 20M rows say more about early training speed and LR than about quality: coarser patches train slower at that budget (3.29 at P = 2 vs 4.37 at P = 16), best lr for E13b at 20M is 3e-3 (the registered 6e-3, copied from E1, is 8% worse; 1.2e-2 is better than 6e-3, non-monotone, so single-seed noise or an instability in the sweep cannot be excluded).
- At 200M bytes P = 2 beats P = 4 by 16% on clean80 at 1.8x the FLOPs; the byte models' clean80 bpc is also 15-20% above their all-val number (memorisation of near-duplicates), the same direction as the token models.
- Patch lag exists and grows with the slot: the last slot of a patch is 7% (P = 4) to 9% (P = 2) worse than the first at 200M; at 20M the P = 2-4 models show 12-15%. Later slots condition on more of their own patch yet are worse than slot 0, so the byte-local decoder does not make up for the one-patch-stale global context; the same ordering shows in the trainers' own `val_loss_slot*` metrics.
- One seed per row, no clean comparison of byte vs token at exactly matched FLOPs (the nearest token runs differ by 0.5-1.9x in FLOPs and in budget/architecture), and the FLOP accounting is the repo's (E13 flops-table). Descriptive.
