## 2. Critique (what the 19:37 review did not cover)

1. **SQ99 has an unaddressed length confound.** sq_99.json gives 400,492 tokens for the 330 out-of-corpus docs and 400,509 tokens for the 1,340 in-corpus docs. That is about 1,210 vs 300 tokens per doc (computed), roughly 4× longer. E1's SWA window is 256 (configs/e1_hybrid.json:8). Long-doc positions beyond 256 depend on GDN state and the single coda attention layer. The scorer uses 1,024-token windows with stride 512 (sq_99_out_of_corpus.py:71, 377–400), so most out-of-corpus scored positions are far from the window edge, and in-corpus almost none are. The gap may therefore be a long-context effect, not the in-corpus memorisation that v0.4.63 proposes. The token-matched sample also does not match document length.
2. **"Does not transfer" is stronger than the data.** The clustered CI [−0.13%, +1.03%] includes small advantages for E1. The data exclude the in-corpus magnitude (about −3.4%), not every transfer. C192 as REFUTED states the sign claim with more confidence than the CI allows. Under AGENTS §0 the wording should be "the in-corpus magnitude does not reproduce" with C192 INCONCLUSIVE, or else the refutation has to be argued explicitly.
3. **SQ99 uses E1 at its untuned LR.** K7 puts E1's optimum at 6e-3, so both the in-corpus and out-of-corpus gaps were measured with E1 about 1.5% handicapped (20M-token estimate). The planned re-run (Phase 2b checkpoints) fixes this, but it should be length-stratified too, or it repeats the same confound at a better LR.
4. **Byte Quest X1 cannot yet separate sharing from parameter count.** The B arm (one block shared ×2) has half the decoder parameters of A′ (two unshared blocks at equal FLOPs). If A′ wins, the result reads as "recurrence does not help" when it may be "more parameters help" (C33 puts recurrence at r^0.46 unique blocks). A parameter-matched arm is needed, so the design is a 2×2 on FLOPs and params, not a single pair.
5. **X1's thresholds may sit below the noise floor.** Predictions 1–3 use 0.3–0.5% relative. C93 (hypothesis) puts the seed sd at ≤ 0.004 absolute on a ~0.6 loss, about 0.7% relative, and nothing measures decoder-only seed noise. Two seeds cannot estimate an sd. Prediction 2 is also internally inconsistent: H-C2F needs B below A′ by more than 0.5%, yet the text says a within-band result "supports H-C2F". Use an equivalence test (TOST-style) for "no difference", and state the sign for "B is better".
6. **X1 caching is not feasible as written.** "Decoder-only training on E1's features, which can be cached" would store 200M tokens × 384 dims × 2 bytes ≈ 154 GB (computed). Either recompute E1's forward on the fly (no grad, about a third of training FLOPs) or cache a 10M-token subset (about 8 GB, computed).
7. **X1 trains the speller on memorised features.** E1's states on train docs are fitted to templates that K9 found in val, so the decoder learns from over-confident states and is evaluated on clean val. Train the speller on tokens E1 did not fit (for example held-out documents), or report the train/val feature shift.
8. **Byte-scale plumbing gap.** The RoPE table is built to max_seq_len = 1,024 (model.py:227). The E12 setting of T = 4,096 bytes would fail at T > 1,024 unless max_seq_len is raised, and the window correspondence (1,024 bytes ≈ 274 BPE tokens at 3.735 bytes/token, analysis note header) should be stated as a matched window. Decoder arms also have no LR tuning step, against AGENTS §6 (controls tuned before use).

## 3. Alternative ideas

Each idea is new compared with side-quests.md, the queue, the 19:37 review (A1–A6, SQ200–SQ205) and the 19:07 review.

- **I1. Length- and family-stratified SQ99 re-analysis (CPU, no training).** Hypothesis [spec]: E1's out-of-corpus gap depends on document length: E1 is better on short docs (≤ 300 tokens) and worse on long ones (> 1,000). Cheapest test: bin the saved per-doc NLL by token count (recount tokens with the tokenizer if counts are not stored), bootstrap by package within bins, and add A1's family membership (27% of docs in families of size ≥ 2) as a second stratifier. Minutes on CPU. Changes plans: a sign flip across length bins makes SQ99 a length result, which moves the decisive re-run to a length-matched design and triggers I2. A flat gap keeps "does not transfer" but in the narrower magnitude form. Novelty: SQ213 clusters by package only; nothing stratifies by length.
- **I2. E1 window sweep: 64 / 256 / 1,024 (= T).** Hypothesis [spec]: E1's in-corpus advantage shrinks as the SWA window grows, because the advantage comes from restricting local attention. Cheapest test: three 20M-token runs at 6e-3, seed 0, with per-length-bin eval (about 15 GPU-min, including compile). Changes plans: a gap that closes at w = 1,024 means the advantage is a local-attention restriction (a regularising effect), not a state-tracking effect; a window-insensitive gap strengthens the GDN story. Novelty: SQ191 removes the global layer and SQ97 varies width; no window sweep is listed.
- **I3. Recurrence-free control for the GDN blocks.** Replace each GDN mixer in E1 with a causal depthwise long convolution (length 256, H3/Hyena-style), with parameters matched. Hypothesis [spec]: it matches E1 within seed noise, so the advantage is a local convolutional inductive bias, not a running state. Cheapest test: one 20M-token run at 6e-3 (about 4 GPU-min) plus about an hour of implementation. Changes plans: if it matches, the "running notes" account (19:37 critique 5) is wrong and the mixer claim must be reworded. Novelty: SQ91 removes ShortConv, gate and out-norm from GDN, but no recurrence-free replacement is listed.
- **I4. Noise floor for X1 before any byte run.** Hypothesis [spec]: decoder-only seed sd on frozen features is ≤ 0.2%, so X1's thresholds are testable. Cheapest test: arm A at three seeds on a cached 5M-token subset, plus a per-layer linear probe on E1 states for the bytes of the next token (about 10 GPU-min; the ridge fit runs on CPU). Changes plans: sd > 0.3% means X1 needs four or more seeds or wider thresholds; the probe shows how much spelling information E1 already carries, which bounds what any decoder can add. Novelty: SQ94 covers confirmatory seed sensitivity, not decoder noise; X1 has no noise test.
- **I5. Weight EMA as an LR-robustness recipe.** Hypothesis [spec]: an EMA of weights (decay about 0.999) closes most of the 1.5% E1 gap at 3e-3 vs 6e-3, so single-LR comparisons become less biased. Cheapest test: two 20M-token runs of E1 at 3e-3, with and without EMA (about 6 GPU-min). Changes plans: if EMA removes the gap, untuned-LR comparisons are more defensible at low cost; if not, per-arm LR tuning stays mandatory. Novelty: SQ11 (Muon) and SQ12 (LR stress) do not test averaging.
- **I6. Frozen test split as the confirmatory out-of-corpus set.** Use code-py-v1-test (462 files, 1.0M tokens, max 13-gram overlap 0.06; A1, v0.4.55), behind its access guard, in place of SQ99's 330 local files. Hypothesis [spec]: E1 vs E0 gives the same sign as SQ99 on the frozen split. Cheapest test: E0 and E1 on about 1M tokens (roughly an hour of CPU, from the SQ99 rate, computed). Changes plans: it replaces SQ99's selection (stdlib and site-packages, filtered by overlap) with a dated, third-party set, and makes the transfer verdict less dependent on local-file choices. Novelty: the split exists, but neither QUEUE nor side-quests schedules E0/E1 on it (grep).
