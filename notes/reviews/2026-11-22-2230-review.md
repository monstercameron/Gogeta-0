## 2. Critique

**Architecture and controls**
1. **The mixer contrast is confounded.** E1 and E10 differ in mixer, init, RoPE layout and RMSNorm eps (configs; 21:40 critique 2). E1 also has 4.5% more non-embedding params (11.1M vs 10.62M, computed). SQ234 covers init only. The honest reading of C5 is "E1 vs E10 as implemented", not "linear-time mixers vs attention". The thesis wording goes beyond that.
2. **"Linear-time" is a FLOP claim, and measured wall-clock goes the other way.** At 13.8M, E1 is slower than E10 on every SKU measured (see 1). Attention is dense-masked (`Attention._mask`), so the O(n) pitch in the README table is untested. SQ244 would measure it.
3. **Nobody has checked that E1's GDN layers do work.** E1 has 3 GDN, 2 SWA and 1 full-attention block. If the trained model can lose its GDN blocks cheaply, the mixer arc is not the thing that matters. Idea A tests this.
4. **The ternary leg is the costliest part of the fusion and has no in-model data.** BitLinear quantises activations to int8 as well as weights (model.py:73-78). SQ192 is right to split the factor. At 14M the K4 proxy predicts about 10% cost, so the fusion has to earn that back before any loop work matters.

**Statistics**
5. **The seed sd figures conflict.** REPLICATION uses a pooled clean80 sd of 0.0010 bpc (0.38% of the mean). SQ214 gives 0.39% at 20M. The brief's factorial pilot gives 0.6-1.2%, but its file is not in what I read. At sd 0.0010, two-sample n = 7 resolves about +-0.4% (computed). At 0.6-1.2% it resolves only +-0.6-1.3%. If the pilot is right, a "tie" at 7 seeds means "no effect above about 1%", and the 0.3% effects the plan cares about are invisible. The pilot needs a pointer before any power number is used.
6. **C196's equivalence margin is too wide to mean much.** The margin is +-1% of E1's mean, i.e. +-0.0027 bpc (ledger). The observed E1-E10 gap is 0.08-0.18%. A +-1% margin would accept a 0.9% loss as "equivalent". The VERIFIED wording should say "within +-1%", and the margin needs a justification before anything is called equivalent.
7. **R1 was weak when registered.** Its sign was not fixed before scoring, and at n = 3 on N1X the Holm family is two tests. The N1X and 5090 runs must stay separate (AGENTS §5 SKU rule). Any pooled estimate is a sensitivity analysis only.
8. **The primary metric reweights sources.** clean80 keeps about 48% of algorithmic-corpus docs but 77% of synthetic docs (SQ225, computed). SQ239 (stratified) is registered but not run. A within-stratum sign flip would make the verdict population-dependent.
9. **Scale is confounded with the token ratio.** At 200M tokens, 14M params is about 14 tokens/param (computed). At 2.3x params (about 32M), the same 200M is about 6 tokens/param (computed). A "2.3x params, 7% better" result at fixed tokens therefore mixes model size with token budget and total compute. AGENTS §5 requires matched compute or matched params plus compute to be stated. The brief does not say which applies to E32/E33.
10. **Unreported results.** A3 clean80 numbers are unreported and were produced on v2 without the SQ238 control. No verdict should rest on them until both are in.

## 3. Alternative ideas

Each idea is new unless marked. None duplicates an item in the queue.

**A. Layer knockout: are the linear-time layers load-bearing?** (new; SQ91 is training-time decomposition, SQ203 is per-token distance binning)
- Hypothesis (spec): in E1, zeroing any one GDN block's mixer output costs at most 0.3% clean80 bpc, and zeroing all three costs at least 2%.
- Cheapest test: inference only, on the seed-0 200M E1 and E10 checkpoints. Zero each block's mixer output in turn (the 3 GDN blocks in E1; each attention block in E10 as the analogue). Score clean80 with the existing scorer. About 5 min on one 5090 (spec).
- Changes plans: if single-GDN removal is nearly free and all-GDN removal costs under 1%, E1's linear layers are not doing the work, so pause the mixer arc (SQ235, SQ243) and the loop-with-GDN work (Q22). If removal costs more than the E10 analogue, the mixer is load-bearing and the open question is efficiency only.

**B. Logit ensemble of E1 and E10** (new; SQ246 is single-model calibration)
- Hypothesis (spec): E1 and E10 make partly different errors, so a 50/50 logit average beats the better single model by at least 0.5% clean80.
- Cheapest test: inference only, on the seed-matched 200M checkpoints (seeds 0-2). About 2 min on one 5090.
- Changes plans: a large gain says the mixers are complementary, so the architecture claim becomes a mixture claim and C5's framing changes. No gain reinforces the tie. The ensemble costs 2x at inference, so it is a diagnostic, not a recipe.

**C. Token-weighted vs document-weighted scoring** (new as an aggregation confound; C101 is packed vs doc protocol, SQ213 is clustering)
- Hypothesis (spec): the E1-vs-E10 sign on clean80 changes between token-weighted and document-weighted bpc.
- Cheapest test: rescore the existing 200M checkpoints (3 seeds each) under both aggregations, and under equal-source weighting. CPU or about 1 GPU-min.
- Changes plans: a sign flip means the registered metric's aggregation drives the verdict. The aggregation has to be fixed in the registration before the next verdict is written.

**D. Distil E10 into E1 at 20M** (new; adjacent to SQ202, which reinitialises mixers, a different question)
- Hypothesis (spec): training E1 on E10's soft targets (KL on the same tokens) closes at least half of any 20M gap. If it closes, the gap is an optimisation-signal problem. If not, it is capacity or inductive bias.
- Cheapest test: 2 seeds, 20M tokens, E10 as frozen teacher at its K7-tuned LR. About 3-4 GPU-min (spec).
- Changes plans: a closed gap means the 200M deficit is about data efficiency, so test distillation at 200M. No closure points to capacity, which makes the width sweep (E) the next step.

**E. Token-ratio-matched width sweep, including the ternary penalty** (partial overlap with SQ243 and SQ97; the new part is the token-ratio control and the ternary leg in the same sweep)
- Hypothesis (spec): at fixed tokens per param (about 14), both the E1-E10 gap and the BitLinear penalty shrink as d grows, in line with K4's ternary trend.
- Cheapest test: d = 256 / 384 / 512, seed 0, token budget 14 x params, for E1, E10 and ternary E1. About 10 min per run on one 5090 (spec, the d = 512 run is the largest).
- Changes plans: if both gaps fall toward zero by d = 512, the 14M verdicts are a small-scale artefact and the fusion is worth scaling. If they stay flat, scale is not the lever and the thesis needs a different ingredient.

**F. Ternary penalty on the dense control** (SQ242; not new, but it is the only leg test that does not need a new mixer)
- Hypothesis (spec): the BitLinear penalty is the same on E10 as on E1, within 0.5%.
- If it is not the same, the "fusion" claim depends on interaction, not on additive gains. Run it with E if E is funded.

## 4. The single experiment to run next

**A, the layer knockout, on existing checkpoints.**
- It is one GPU job of about 5 minutes, on seed-0 200M checkpoints already on disk (paths are on the E1 and E10 cards; I did not verify them). It needs no training and no new config.
- It is a gate. Idea E, SQ243, the efficiency work and any loop-with-GDN run all assume the linear-time layers do something. If the knockout shows they do not, those runs are wasted compute. If it shows they do, E is justified and the efficiency question is what remains.
- It does not depend on the v2 dispute or the wave-3a results, so it can run now.
- Pre-register before reading: the single-GDN knockout cost, the all-GDN cost, and the E10 attention analogue, all on clean80 with the existing scorer.
- Caveat (spec): zeroing a trained block measures how much the trained function depends on it, not whether the untrained architecture needs it. A stronger claim needs a retrained variant.
