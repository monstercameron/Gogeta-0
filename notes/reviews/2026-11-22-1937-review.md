## 2. Critique

1. **The E0 gap is an implementation gap, not an LR gap.** E10 at 3e-3 is the same LR as E0's untuned 3e-3, and K7 puts E10's optimum at 3e-3. So LR cannot explain a 3.6–4.1% gap. Code differences I can verify: (a) init. E0's residual-output weights get std 0.02/sqrt(2·depth) = 0.0058 (model.py:247–250); E10 gets 0.02 everywhere (configs/e10_llama_ref.json description). (b) Depth for that formula comes from cfg.loops in looped models (model.py:241–244), so E1 and E2's init scale depends on loop bookkeeping, a second confound across E0/E1/E2. (c) RMSNorm eps 1e-6 (E10) vs torch's default, and interleaved RoPE pairs (model.py:99–100) vs HF's half-split. [spec] (c) is probably a permutation of head dims, and probably small. The step-0 loss match (9.094) tests the forward pass only, not training dynamics, so the difference shows up later in training. Consequence: every E0-based number inherits it: C5, the E2-vs-E0 +2.0% (C6/C7), SQ99's ratio, and the K9 E0 bits/char. Only one E0 seed exists, so E0's seed noise is unknown, but two E10 seeds both sit 3.5% below it.

2. **Possible horizon flip (new, needs checking).** Matched LR, seed 0: at 20M (K7), E1 at 3e-3 is 1.0071 vs E10 1.0286, so E1 is 2.1% better. At 200M, E1 at 3e-3 is 0.5846 vs E10 0.5822, so E10 is 0.4% better. Each model at its own tuned LR at 20M gives E1 −3.5%. If the 20M and 200M protocols are the same (not verified: the 19:07 review mentions a "packed protocol" for K7), the hybrid's advantage may be an early-training effect that shrinks with tokens. No registered arm tests this, because A3 is fixed at 200M.

3. **SQ99 is at risk of a biased verdict.** It scores E1 against E0 and decides "transfers" on gap < 0 with a CI excluding 0 (v0.4.54). A baseline that is 4% worse in-corpus can make a gap look like it transfers out of corpus. SQ99 should be re-scored against E10 before its verdict is written.

4. **Validation is contaminated in an unknown direction.** 41.7% near-duplicate val means an architecture that memorises more can look better. Both headline comparisons use full val. Until the clean80 re-score (SQ100) runs, the sign of any gap is not interpretable, and that is the case for E10-vs-E1 too.

5. **The mechanism is asserted, not measured.** The README's "running notes plus a glance at recent lines" account of why E1 wins has no per-token test. The 19:07 review covers the loop; this gap is for the mixer. Nothing in the queue says where E1's loss advantage lives.

6. **Predictions are miscalibrated, and n = 1 is treated as a result.** The K7 prediction missed on the optimum and on flatness. A1 missed on family share (27% vs a predicted >40%). Predictions should carry intervals, and single-seed differences of 2–4% should be labelled as exploratory.

## 3. Alternative ideas

Each idea is new compared with side-quests.md, the queue and the 19:07 review (SQ96–SQ99, SQ190–SQ195, E40–E48). Costs assume ~210k tok/s dense and ~100k tok/s hybrid, plus compile overhead.

- **A1. Init-matched 2x2 (E0 and E10 each with the other's residual init).** Hypothesis [spec]: the residual-output init scale explains most of the E0–E10 gap. Cheapest test: 20M tokens, seeds 0 and 1, four arms (E0 with HF init; E10 with E0 init; E10 already has 20M s0 in K7), about 15–20 GPU-min with compile. Changes plans: if the gap closes, re-base every E0 comparison on E10. If it does not, trace per-layer activation statistics at step 0 and during the first 1k steps (CPU for a 1-layer check). Novelty: SQ93 varies params, not init; K7-PARITY checks step-0 loss only.

- **A2. Horizon learning curve for E1 vs E10 at matched LR.** Hypothesis [spec]: the hybrid's matched-LR advantage shrinks with tokens (2.1% at 20M, 0.4% the wrong way at 200M). Test: seed 0, both models at 3e-3, at 5M, 20M and 60M tokens (200M exists); about 20 GPU-min. Changes plans: a sign change before 200M means C5 and A3's 200M design both need rethinking and E4 needs a longer horizon check. A flat gap supports the claim. Novelty: SQ33 and SQ96 vary tokens for loop and time, not the mixer's horizon dependence.

- **A3. Conversion test: swap mixers in a trained dense model.** Hypothesis [spec]: converting E10 (200M checkpoint) to the E1 layout by reinitialising the mixers and training 50M more tokens recovers most of E1's loss. Test: a conversion script plus 50M tokens (about 5 GPU-min for the run, plus the script). Changes plans: if conversion reaches E1 within 1%, the mixer choice is late-binding and the hybrid is not a from-scratch property. If it does not, E4's full fusion must be trained from scratch and the conversion route is closed. Novelty: not in the queue. I have not searched the literature on hybrid conversion, so the prior is mine, not sourced.

- **A4. Per-token paired loss decomposition (E1 vs E10 on clean80, inference only).** Hypothesis [spec]: E1's gains concentrate on tokens whose evidence lies inside the GDN memory, not on long-range copies beyond the 256-token window. Test: on 500 clean docs, bucket the paired per-token loss difference by token class (identifier, keyword, whitespace, string, number), by position, and by distance to the last occurrence of the same identifier (inside vs outside the window). CPU only, about 5 min per model, using SQ99's scorer. Changes plans: uniform gains point to a generic optimisation effect (and make the "running notes" story unsupported). Gains concentrated at long distances support the SWA-window reading. Novelty: SQ90 uses synthetic probes, SQ194 uses formatting; no real-data decomposition is listed.

- **A5. N-gram copy floor (no neural model).** Hypothesis [spec]: on the near-duplicate band (>80% overlap), a 5-gram model trained on the 200M train tokens comes within a few percent of E1, so K9's memorisation gap is mostly copying. Test: write a Kneser-Ney 5-gram in plain Python (no install), score the three K9 bands, CPU, about 10 min. Changes plans: if the copy floor explains the band, the K9 delta (+25.8%) is not a capability signal, and the primary metric should be the <50% band. Novelty: K9 uses only neural scorers, and SQ95 is scorer parity, not a copy baseline.

- **A6. Cheapest-check ordering (meta).** Hypothesis [spec]: running A1 and A5 (CPU and one GPU job, about 25 min total) before Phase 2b's verdicts would change which E0-based claims are worth registering. Test: none; this is a scheduling change. Changes plans: if A1 shows the gap is init, C5 and SQ99 must be re-scored before the Phase 2b verdicts are written.
