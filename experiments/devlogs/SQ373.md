# SQ373: close reward forgery in the rewards.py test harness

**Status:** done for the probe's cases (residual risk stated) · **Verdict:** exec/compile no-op, AssertionError swallowing, `__main__`/`sys.modules` tampering, os._exit/sys.exit, print-forged result lines, trace hooks and background threads now all score 0 on a failing test; honest pass/fail controls and partial credit unchanged · **Links:** `post_training/rewards.py` (`_HARNESS`), `post_training/test_rewards.py` (`TestForgery`), probe `experiments/checks/reward_forgery_probe.py`, claim C83

## Change
The child harness is now a GRADER process that forks a WORKER (the worker runs solution + tests; both children of the same namespaced sandbox, same rlimits). Defences: (1) every function used after the solution runs (exec, compile, BaseException, str/len/type/dict, os.read/write/fork, json.dumps/loads, settrace/setprofile, threading.active_count) is bound before it runs, so patching builtins, os, json, `sys.modules` or `__main__` cannot change the test run; (2) each test runs in its own fresh shallow copy of the solution's namespace with a pristine copy of the builtins; (3) no secret in the worker while the solution runs: the stdin nonce is dropped in the worker and a per-run inner nonce is generated by the grader and sent only after the worker reports the solution finished; (4) the result comes back over a pipe, the grader checks the inner nonce and the structure (0 <= passed <= total == number of tests) and is the only writer of the final nonce-tagged line, so a worker that exits early or prints a forged line yields "no result"; (5) a solution that leaves extra threads or a trace/profile hook is scored as failed ("TamperingError").

## Tests (`python -m unittest post_training.test_rewards`, 30 OK; 4 new in `TestForgery`)
Controls: honest pass scores 1/1, honest fail 0/1, partial credit 2/3 unchanged. Eleven forgery cases (the probe's exec_noop, compile_noop, assertionerror_swallow, sys_exit/os._exit(0) plus: patching BaseException/str/len/type/dict/int/isinstance, `__main__._report/_res/_main`, fake `json` in `sys.modules` and patched `os.read/write`, a printed forged result line, `sys.settrace`, a live background thread) each score 0 against `["assert f() == 2", "assert False"]` under fs_isolation "off" and "auto". Probe re-run: exec_noop and compile_noop now 0/1 (before: 1/1 in both the committed and working-tree harness). `evals/sandbox.py` self-test still ok (17 checks) and `tests.test_sandbox_gate` 6 OK, since it delegates to the same harness.

## Residual risk (not closed)
Code in the worker can still imitate the worker's side of the pipe protocol (find the fds via /proc/self/fd, write READY, read the nonce, write a forged result) or defeat the tests from inside the objects they check (return an object whose `__eq__` is always true; mutate shared objects). Closing those needs the tests to run in a process the solution cannot touch (a separate interpreter that imports the solution as data) or a pid/fd-isolated grader; not attempted. Per-test cost: one extra fork per scored program (a few ms). Process sandbox, not a security boundary.
