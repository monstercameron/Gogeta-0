# SQ366: optional per-doc NLL storage in score_doclevel.py

**Status:** done · **Verdict:** `score_doclevel.py --store-nll` writes `<run>.nll.npz` (per-subset doc indices, per-doc NLL in nats, per-doc token counts; compressed) next to the aggregate JSON; default off, aggregate output unchanged · **Links:** `experiments/stats/score_doclevel.py`, `experiments/stats/test_score_doclevel_hashes.py`

K8's `score()` computes per-doc NLL but does not return it (and K8 is not in my file set), so `score_perdoc` is a copy of its chunking/windowing that also returns `nll_doc` and `tok_doc`; with the flag, `K8.score` is swapped for it (`score_checkpoint` resolves `score` in K8's globals). Helpers `save_nll_npz` / `load_nll_npz`. The JSON gets `nll_npz: <file>` only when the flag is used. Test (CPU, fake logits, windows 1024 and 64, short and multi-window docs): totals equal K8.score to 9 places (bits/char, nats/token, tokens, chars), per-doc tokens sum to the total, per-doc NLL reproduces bits/char; npz round trip. 8 tests OK (`python -m unittest experiments.stats.test_score_doclevel_hashes`). The GPU path itself was not run (no GPU); the swap is the only change on that path.
