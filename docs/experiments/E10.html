Experiment E10 · Scouter Calibration

Reference control: Hugging Face Llama at E0's size

Charging config configs/e10_llama_ref.json

The question: Is our own dense baseline (E0) a fair yardstick? Hugging Face's unmodified LlamaForCausalLM at exactly E0's size (13.77M params, 10.62M non-embedding, same FLOPs), trained with the same data and loop at its own tuned learning rate and 3 seeds, becomes the control every other model is compared to.

What it will test, in plain English

Is our yardstick straight? Every result so far compares our models against E0, a standard design we wrote ourselves and trained once, with a learning rate (how big a step the model takes each update) that nobody tuned. If E0 was accidentally handicapped, our new designs look better than they are.

E10 replaces it with a reference we didn't write: Hugging Face's standard Llama model, built at exactly E0's size (13.77M parameters, the same arithmetic per token). It gets its own tuned learning rate and is trained 3 times with different random seeds, so we can see how much results wobble by chance. From then on, a new design only "wins" if it beats E10 by more than that wobble.

Prediction (written before the run)

Written 2026-11-22, before any E10 run. E10 = transformers 5.24.0 LlamaForCausalLM at E0's shapes: 13,767,552 total / 10,621,824 non-embedding params and 96.76M train FLOPs/token, all identical to E0 (computed, check k7_e10_parity.py). (1) At its K7-tuned LR, 200M tokens, seeds 0/1/2: mean full-val loss 0.595-0.615 (most likely ~0.603), seed std <= 0.004. (2) Implementation parity: E0 at the same LR lands within E10's mean +- max(3 x std, 0.5%), i.e. HF's init (std 0.02 everywhere, no residual-output scaling), half-split RoPE and eps 1e-6 change little. (3) E1 at its own tuned LR still beats E10: mean(E1) < mean(E10) by 1.5-4% (the 3.6% gap vs untuned E0 shrinks but survives tuning). (4) Compiled throughput within +-20% of E0 (about 170-250k tok/s steady). (5) Stable: no train-loss jumps > 0.5 after warmup. Pass criteria: experiments/checks/PREDICTIONS.md (K7, replication).

What we'll run

  • Learning-rate tuning (check K7): short runs (20M tokens) at four learning rates for E10 and for our best design, E1. Each model gets the rate that scores best, picked by a rule written down before the runs.
  • Replication: E10 and E1 at their tuned rates, 3 seeds each, 200M tokens.
  • Parity: if E10's tuned rate differs from the one E0 used, E0 is re-run at E10's rate. That tells us whether our own dense model was a fair stand-in.

The predictions and pass criteria were written before any run, in the registry and in experiments/checks/PREDICTIONS.md.

Status

Planned. Its config and launch script are ready (configs/e10_llama_ref.json, experiments/launch/E10.sh). A CPU check confirms E10 has exactly E0's parameter count and per-token arithmetic. Nothing has been trained yet.
