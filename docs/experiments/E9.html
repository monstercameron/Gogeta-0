Experiment E9 · Shadow Clone

Unlooped control for E2

Fusion stable recorded in v0.4.79 config configs/e9_unlooped.json

The question: Same 5 blocks as E2 ([SWA] [GDN, GDN, SWA] [attn]) trained once, without weight sharing or loops. Is weight sharing plus ~4 passes better than one pass of the same blocks? This separates the effect of looping from depth and parameter count.

What it will test, in plain English

Is it the loop that hurts, or something else? E2 (the looped model) did worse than the others, but it differed in two ways at once: it reuses the same layers several times, and it has a different set of layers. E9 takes E2's exact layers and runs each once, with no reuse and no loop.

  • If E9 beats E2: looping those layers is genuinely worse than just running them once.
  • If E2 beats E9: looping is buying something, it's just expensive.
Prediction (written before the run)

Written 2026-11-22 before the run. E9 (5 unshared blocks, 9.17M non-emb, 0.079 GFLOP/token) lands at val loss 0.590-0.610: a bit worse than E1 (one fewer block) and about equal to E0. That would mean it BEATS E2 at r=4 (0.619) with 41% of the FLOPs, so at this scale looping the same blocks 4x is worse than running them once, untied. If instead E9 > 0.619, looping is genuinely buying something and E2 just pays for it in compute.

Status

On hold. The first attempt was started (from commit eecdaeb), but it was interrupted at 10% of training when the agent session ended, so there are no results. Training is paused for now, and E9 will be re-run when it resumes.

Planned re-run: seed 0 in the Phase 2 replication campaign, at the learning rate tuned for E1 (E9 is E1's layout minus one block). Its prediction was written for lr 3e-3; it stays unedited and is scored as written, with the learning-rate difference stated. If that tuned rate isn't 3e-3, E2 is re-run at the same rate, so the loop question is answered at one learning rate.
