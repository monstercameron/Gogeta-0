GOGETA-0

The first FusionDance language model

Three efficiency techniques that each beat one cost of modern LLMs: context, parameters and bits. Fused into one small model for Python code. Naively the three penalties compound. The assembled recipe recovers most of the loss, and every component now trains and runs together. It is not yet competitive with a plain dense model, and the research is paused for the next decisions.

The fusion

The FusionDance architecture, as trained

A2s, the best assembled recipe: a full-precision prelude and coda around one shared, ternary core that runs twice.

What the measurements say

The data-flow atlas instrumented this model at every layer boundary.

  • The first sliding-window layer behaves like a plain moving average.
  • Pass 1 transforms the state; pass 2 refines it.
  • Every pass shrinks perturbations, so the loop is stable.
  • The coda does the most work on unfamiliar code.
  • int8 activations are safe.

These readings are descriptive.

  • Gated DeltaNet: linear-time mixing with a fixed-size memory that can overwrite. Its heads learn horizons from about 7 to over 2,000 tokens.
  • Sliding-window attention: exact attention over the last 256 tokens. Our kernel still uses a dense mask, so it is O(n²) for now.
  • The loop: the same ternary weights run twice. A fixed count beats a random one (C212 PARTIAL), and unique parameters still buy more per FLOP than a second pass (C197).
  • Contractive injection: the prelude's output is re-injected before each pass through a learned gate, so the state cannot blow up.
  • Full-precision ends: the prelude, coda and injection stay full precision. On the naive fusion that alone is worth −7.6%. A ternary prelude barely writes anything.

Side quest

Byte Quest: coarse-to-fine bytes

No tokenizer, exact characters, and a 256-way head. A global stack runs on patches, and a small shared loop refines at byte resolution. Tested, and not viable at this scale yet, as the literature predicts below about 4B parameters on code.

  • Fixed byte patches (E13): +36% and +63% bits per char vs E1. Far too costly. (exploratory)
  • Tokens as patches around the A3 backbone (A4, E65): +14.4% vs the token head. The second shared byte pass does help (−1.7%). C210 UNVERIFIED
  • Next: the design-around is SQ394. E12 and E14–E16 are registered but not run.

The science

Three budgets, measured separately

n = context length, L = layers, r = loop count, S = fixed recurrent-state size. The FusionDance column is the design target. Today our sliding-window layers still use a dense-mask kernel (O(n²)), and ternary weights are simulated in floating point, so the speed and memory wins need dedicated kernels.

Big ideas

What we're testing next

Each idea is stated so it can be shown wrong, and each card says where it stands.

⚖️

Is the A2 bundle just more bits?

C215's −6.85% may come mostly from the full-precision ends. A bit-matched control (SQ447) gives the naive recipe the same ends.

Registered idea; first in the next GPU batch
🪶

An attention-free first layer

The first sliding-window layer acts as a moving average. Swapping it for an exact window mean costs at most 0.4% out of corpus, so train it that way and drop its attention (SQ442).

Eval-only check done; training test queued
⚡

Instant transmission

A looped model drafts for itself: one pass guesses, two passes verify. No separate drafter.

Built; exact losslessness needs batch-invariant kernels
📈

Does it hold at scale?

Every result is at ~15M parameters. A mid-scale run against dense, judged on quality per byte and tokens per second, comes before the 1.2B model.

Needs the bigger dataset and a go-ahead
